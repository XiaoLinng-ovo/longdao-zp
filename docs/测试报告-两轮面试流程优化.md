# 两轮面试流程优化测试报告

## 1. 测试对象

招聘流程固定为两轮：

- 初试：通过后进入复试。
- 复试：通过后进入 Offer 流程；未通过则结束申请。

## 2. 原始问题

在最终轮点击“进入下一轮”时，系统没有第三轮可生成，面试记录和申请状态也可能出现不一致。前端虽然已经隐藏了复试的“进入下一轮”选项，但通用 `/conclude` 接口仍可能接收该结论；同时，服务层和仓储层原先允许手工创建第三轮面试。

## 3. 优化方案

1. 统一前端、服务层、仓储层的两轮规则，不能只依赖前端隐藏选项。
2. 初试只允许“进入下一轮、未通过、取消面试”。
3. 复试只允许“通过进入 Offer、未通过、取消面试”。
4. 禁止创建第 3 轮，也禁止重复创建初试或复试。
5. PostgreSQL 创建面试时锁定申请记录，避免并发请求生成重复轮次。
6. 非法结论在写入面试记录、申请状态、流程事件前直接返回，不产生部分更新。
7. 保持重复提交的幂等行为：同一结论重复提交不会重复创建复试或重复写入结论事件。

## 4. 已实施修改

- 统一结论校验函数，服务层和 PostgreSQL 仓储层都执行复试终轮校验。
- 增加两轮上限校验：轮次只能为 1 或 2。
- 增加同一申请下轮次唯一校验。
- PostgreSQL 创建面试时增加申请行锁和已有轮次检查。
- 增加复试提交“进入下一轮”不改变申请状态、不改变面试状态的回归测试。
- 增加第三轮创建被拒绝的服务层和仓储层测试。

## 5. 测试结果

### 已通过

- API 构建：通过。
- 初试推进、复试终轮校验、重复提交幂等：13 项通过。
- PostgreSQL 仓储相关面试 SQL 契约：4 项通过。
- Web 初试和复试结论页面：14 项通过。
- 代码格式检查：通过。

### 数据库集成测试

首次运行时，测试命令没有把仓库根目录 `.env` 加载到 Node 测试进程；集成测试通过 `process.env` 判断连接凭据，因此误将测试标记为跳过。这不代表本机没有 PostgreSQL：本地数据库已配置且可连接。

随后将 `.env` 注入测试进程，直接运行 PostgreSQL 集成测试，2 项均真实执行并通过，覆盖面试完成事务、申请状态、Offer 资格、企业隔离，以及结论后关闭实时面试会话。

单独重新构建 API 时，构建被现存的平台管理员类型错误阻断（`PlatformService.requireSuperAdmin` 缺失及平台角色类型不匹配）；这些错误不在本次两轮面试改动范围。数据库集成测试本身通过。

## 6. 验收标准

- 初试点击“下一轮”后，只生成 1 条复试记录，申请状态为“面试中”。
- 复试页面不显示“进入下一轮”。
- 通过复试后，复试状态为已完成，申请进入 Offer 流程。
- 复试提交“进入下一轮”时返回明确错误，不创建第三轮，不改变申请状态。
- 任何入口都不能创建第 3 轮或重复创建同一轮次。
- 重复点击确认不会重复创建记录或重复写结论事件。
