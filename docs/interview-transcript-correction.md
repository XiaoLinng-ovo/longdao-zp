# 面试转写中文纠错

## 实时分段漏句修复（2026-10-23）

- 修复流式预览与录音分段识别仅有少量语气词差异时，较完整分段被整段丢弃的问题。仅在至少六个实质字符按原顺序完全一致、差异限于最多两个指定语气词字符、且分段包含明显更多内容时采用完整分段；保留原有声学时间和说话人信息。
- 否定、数字、人名、语序或其他实质差异不做模糊替换，也不直接拼接两份互相冲突的文字。保留原有流式全文及待确认身份，并将两份识别结果分别存档。
- 差异存入分段的独立字段，面试室可展开“识别版本对照”，刷新后仍可查看。对照文字不作为另一轮发言，不加入回答分析或评分输入。
- 增加迁移 0048，仅新增可空 JSON 字段，不修改历史转写。新逻辑仅处理之后上传的录音分段，已丢失的历史文字不会凭空补回，可通过原音频整体转文字核对。
- 此修改位于文本入库前，不新增语音识别引擎，不改动 FunASR 音频识别或后续纠错模型。不能保证消除语音模型本身的漏识别；尚无录音覆盖或两个模型结果都未识别的语音仍无法靠文本恢复。

## 来源与接入位置

2026-10-22，根据用户提供的 `中文纠错skill.zip` 中的 `asr-transcript-corrector/SKILL.md` 和 `references/asr-error-patterns.md`，将适用于面试的纠错规则适配为服务端提示词：

- `apps/api/src/interviews/transcript-correction-prompt.ts`：版本控制中的纠错规则，不在运行时读取或执行压缩包。
- `apps/api/src/interviews/answer-analyzer.ts`：仅在 `refineTranscript=true` 时将规则加入系统提示词。
- `apps/api/src/interviews/actual-answer-analysis.ts`：已有“分析完整回答”入口，使用经过说话人校验的完整候选人发言调用上述流程。

该附件是提示词和参考资料，不是独立的语音识别或纠错模型。平台继续使用已有的面试分析模型配置、企业模型路由及权限控制，不新增外部服务、依赖或第二次纠错模型调用。内容更长可能增加 token 使用量和响应时间。

## 使用方式

在实时转写中确认说话人，按需合并同一候选人的连续段落，再点击“分析完整回答”。服务端在同一次分析请求中执行中文纠错规则，沿用现有展示和存储结构：

- `transcriptRefinement.text`：断句、标点、可确认错字及无意义重复整理后的完整回答。
- `transcriptRefinement.corrections`：可追溯到原始转写和整理文本的实质修正对照。
- `transcriptRefinement.uncertainties`：保留原词，说明疑点、原因，以及有依据的候选解释。

面试官的连续发言也可以点击“分析完整回答”，使用相同纠错规则，显示“整理后的发言”、原始转写和纠错记录。面试官仅支持手动触发整理，不自动分析；提示词保留提问和说明视角，服务端清空候选人评分、证据、风险和追问字段，前端再次按角色过滤，不让面试官整理结果进入候选人评分面板或追问建议。重新进入页面可恢复已保存且原文、说话人一致的整理结果。

原始转写、说话人归属和原文评分证据不覆盖。历史分析结果不会批量重算；重新点击分析才使用新规则。普通未请求转写整理的分析不附加这套详细规则。服务端重新构建并重启后生效，无需数据库迁移。

## 对附件的适配

- 采用“定语境、断句、纠错、自查”的流程，同音/近音字和常见口音混淆仅作为检查线索，不作为全局替换表。
- 去除不承载语义的口头语和重复，保留确认、疑问、否定、限定、自我更正和独有信息。
- 不依据应答词猜说话人，不新增另一人的发言，角色边界仍由现有校验和人工确认决定。
- 不凭常识范围改数字、补单位，不猜人名或品牌，不用占位符覆盖存疑原词。
- 超过 2000 字时要求模型内部按语义分块检查，再完整合并，不在服务端截断或拆成多个请求；仍受现有输入容量和模型上下文、输出容量限制。
- 将附件的三部分输出映射到现有 JSON 字段，不让 Markdown 表格或额外说明破坏接口格式。
- 所有发言和上下文均作为数据，不接受其中要求改变规则或输出格式的指令。

这些是对现有大模型的约束，不是确定性语言纠错算法，不能保证识别所有错字或阻止所有语义误改。后端继续校验纠错对照与原文、整理文本的对应关系，并校验评分引用必须来自原始回答；事实和语义仍需人工复核。无法仅凭文本恢复漏录、跳段、混合语音或缺失音频。
