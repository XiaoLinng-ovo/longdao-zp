# 企业通用简历评分 Skill 模板

这是一套面向企业招聘 ATS 的通用评分协议，适合先绑定到多个岗位，再按岗位族复制调整。它把开源简历解析、岗位匹配和候选人筛选项目中反复出现的可验证能力、经历相关性、资格门槛和场景匹配合并为六个维度。

## 使用建议

- 先按岗位族复制模板，例如研发、销售、财务或运营，再调整技能和硬性门槛的具体描述。
- 保持权重总和为 100；每次调整都保留规则快照，便于解释历史评分。
- 用一批已由招聘团队人工复核的历史简历做回放，检查证据引用、`not_mentioned`、`contradicted` 和总分分布。
- 将模型评分作为复核排序信号，不作为自动拒绝、自动录用或自动发送 Offer 的唯一依据。

## 可直接使用的 Skill 正文

```text
企业通用 · 证据驱动简历评分 Skill
总分 100 分。只能依据脱敏简历中明确写出的事实评分；没有证据就标记 not_mentioned、0 分、待核实，不得从公司名称、岗位名称、学校、年龄或常识推断能力。每个维度必须返回 score、maxScore、status、sourceTexts、rationale，sourceTexts 必须逐字引用连续原文。

一、硬性要求与资格门槛：20 分
核对岗位明确要求的学历、证书、语言、地点、工作许可、最低年限和其他不可替代条件。满足给分，部分满足按证据给部分分，明确冲突为 contradicted、0 分并列为风险。硬性条件只影响匹配判断，不得因为未提及直接判定不符合。

二、核心技能与岗位能力：25 分
评估岗位所需技能是否真实使用过、使用深度、技术或业务范围和独立程度。仅出现关键词不给满分；区分了解、参与、负责和主导。优先采信带有职责、工具、方法和结果的项目证据。

三、相关项目与工作经历：20 分
评估经历与岗位的相关性、职责边界、项目复杂度、规模、持续时间和量化结果。协助、执行、负责、主导必须区分；优先评价可验证的产出、指标改善和交付结果。

四、业务与行业场景匹配：15 分
评估候选人是否处理过相近的客户、产品、行业流程、合规约束或业务问题。相近行业可以部分得分，但不能仅凭公司名称或行业标签推断。

五、教育、专业资质与持续学习：10 分
只评估与岗位相关的专业、学历、证书、培训或持续学习记录。证书必须以简历明确内容为依据；与岗位无关的学历或证书不加分。

六、成长轨迹与岗位潜力：10 分
评估职责范围是否逐步扩大、是否有跨项目迁移能力、是否能从已有证据合理判断学习潜力。潜力只能来自明确的学习、转型、复用或改进事实，不能用空泛表述补分。

统一规则：
1. 总分按各维度实际得分与满分加权换算为 0-100；服务端重算总分，不信任模型自行填写的总分。
2. 每个维度给出一至两条最相关原文、得分理由、缺失信息和风险；未提及不等于不符合。
3. status 只能使用 supported、partial、not_mentioned、contradicted、待核实等系统约定值；not_mentioned 必须为 0 分且无证据，contradicted 必须为 0 分。
4. 不得以姓名、性别、年龄、婚育、民族、籍贯、照片、残疾、宗教或其他与岗位能力无关的个人属性加减分。
5. 沟通、团队协作、性格、文化匹配等泛化软技能不单独计分，除非岗位要求具体定义了可观察行为和证据。
6. 评分结果仅供招聘人员复核，不自动淘汰、录用、发送 Offer 或改变申请状态；疑似冲突、证据不足和硬性条件缺失都列为待核实。
```

## 岗位族调整建议

复制模板后只调整岗位相关的证据标准和硬性门槛，保留六个维度的结构与状态规则。研发岗位可以在“核心技能”中细化语言、框架、架构和交付质量；销售岗位可以细化客户类型、销售周期、回款和业绩口径；财务岗位可以细化准则、系统、审计和合规；运营岗位可以细化用户、渠道、活动和指标增长。

每个岗位版本都应保存版本号、生效时间、调整原因和审核人。上线前使用人工复核样本做回放，重点检查证据是否连续逐字、同一候选人在不同岗位上的分数是否可解释，以及缺失信息是否被错误当成负面证据。
模板来源于对 `interviewstreet/hiring-agent`、`sliday/resume-job-matcher`、`srbhr/Resume-Matcher`、`tanujtp/ai-resume-screening-engine`、`xitanggg/open-resume` 和 `opendatalab/MinerU` 等项目的功能侧重点归纳。项目对比用于提炼评分维度，不代表这些项目之间存在统一标准，也不代表本模板已证明模型准确率。
