# 招聘系统公网访问优化方案

日期：2026-10-27（Asia/Shanghai）

状态：阶段 A+B 已在独立端口完成验证；公网隧道切换仍待确认。

本次只新增方案文档，不修改业务代码、配置、数据库和隧道，不执行构建、部署或重启。下述内容均为拟实施工作。

## 1. 目标与边界

- 减少公网首屏、刷新和页面切换等待，保留登录、企业空间、上传、录音和实时语音功能。
- 不清空数据，不降低鉴权、CSRF、租户隔离和文件校验要求，不升级框架或开展无关重构。
- 独立端口验证后再决定是否切换，保留开发服务和旧资源以便回退。
- 生产构建不能保证消除跨境延迟，固定域名不等于网络加速。
- 新增依赖、账户授权、DNS 修改和付费资源另行确认。

## 2. 当前证据与结论边界

以下为 2026-10-27 在项目电脑采集的请求样本，不代表所有客户端，也不代表整页加载时间。

| 请求 | 本机 | 经临时隧道 |
| --- | --- | --- |
| `/login` HTML | 约 12 ms | 约 1.40 s |
| `/api/v1/health` | 约 2 ms | 多次约 0.75～1.48 s |
| `/src/main.ts` | 约 1 ms | 约 1.43 s |

curl 样本包含各次建连开销，不能直接相加推算浏览器首屏时间。

```text
当前：浏览器 -> Cloudflare -> cloudflared -> Vite 开发服务器 5174
       /api -> API 3100
       /funasr-stream -> FunASR 10095/stream
```

- 进程和 HTML 确认存在 `/@vite/client`、`/src/main.ts`，当前公网仍交付开发模块。
- `web/vite.config.ts` 包含 API 与语音 WebSocket 代理，不能只换静态服务器而丢失代理。
- `deploy/Dockerfile.web` 也启动开发服务器，后续容器部署需同步考虑。
- 页面已使用动态导入，不把缺少路由懒加载直接认定为问题。
- 隧道日志连接位置为 `lax07`，提示跨境链路可能有影响，但不能定位全部延迟，也不代表用户入口节点。
- 日志有上传/音频请求取消及上传请求体未传完整记录，不能单凭它们认定隧道丢包或解析慢。

结论：优先减少前端多轮模块加载，再测网络。本机健康接口快不等于所有业务接口都快；尚缺浏览器瀑布、FCP/LCP 和上传链路分解，不承诺具体提速倍数。

## 3. 分阶段方案

### A. 建立基线

1. 固定客户端、浏览器、账号权限和网络，分别测试本机及公网。
2. 登录页、工作台、简历列表的冷/暖缓存各测至少 10 次，记录中位数及范围。
3. HTML、静态资源和健康接口各测至少 20 次，记录 DNS、建连、TLS、TTFB、总耗时及 P50/P95；小样本 P95 仅作趋势参考。
4. 记录请求数、传输体积、关键依赖链、FCP/LCP、控制台错误和环境说明。
5. 分开计时登录、初始化、上传传输与后台解析。报告脱敏；公网业务测试只用批准的合成数据，不发送真实简历/录音或调用付费模型。

交付：基线表、瀑布/截图。不重启当前业务服务。

### B. 生产构建与同源网关（优先）

```text
浏览器 -> Cloudflare -> cloudflared
  -> 独立本机网关，例如 127.0.0.1:5180
       web/dist：生产静态资源
       /api/* -> API 3100，保持原路径
       /funasr-stream -> FunASR 10095/stream
```

1. 复用现有 `vite build`，不升级 Vue/Vite，不为绕过包管理问题修改无关工作区配置。
2. 核对当前工作区和待发布版本，避免意外发布其他未验证改动；记录发布清单并保留旧资源。
3. 先核查可复用的静态服务能力；不足时优先评估 Windows 可维护的 Caddy 网关。安装方式和新增依赖先确认，不默认安装。
4. `vite preview` 仅用于临时验证构建，不作为长期公网服务器。
5. 网关绑定回环地址的独立空闲端口，保留 Vite，不抢占其他项目端口。
6. SPA 回退只作用于前端路由；缺失 API、JS/CSS 和其他静态文件不得返回 HTML。
7. 保持 API 同源，验证 Cookie、HTTPS 代理头、Origin 与 CSRF，不开放全部来源或绕过安全校验。
8. 保持 WebSocket 升级、路径重写、查询参数、鉴权和断线恢复；实时流不启用阻塞输出的缓冲。
9. 独立端口回归通过后告知切换窗口，经确认再修改本项目隧道目标。重建 Quick Tunnel 可能更换地址，不承诺保留旧链接。

| 对象 | 缓存/传输策略 |
| --- | --- |
| HTML / SPA 入口 | 重新验证，不设长期 immutable 缓存 |
| 内容哈希 JS/CSS | 长缓存、immutable，保留上一版资源供旧页面使用 |
| 无哈希 public 文件、音频 worklet | 短缓存或重新验证，不套用哈希资源策略 |
| JS/CSS/HTML 文本 | 网关支持时协商 gzip/Brotli，正确处理响应变体 |
| 鉴权、企业数据、API | 不启用共享 CDN 缓存，不缓存身份相关响应 |
| 上传、音频、实时流 | 不为静态加速改动上传限制、重试规则或流式行为 |

交付：专用网关配置、启动入口、测试及性能报告。容器同步需单独批准，不默认修改 `deploy/Dockerfile.web`。

### C. 隧道网络与稳定性（按测量结果执行）

1. 同目标、客户端和相近时段对比 QUIC 与 HTTP/2，测延迟、错误率及上传。尽量使用独立测试隧道，避免反复中断现网。
2. 不预设 HTTP/2 更快，不以修改 DNS 或猜测节点声称加速；收益明确再改协议。
3. 整理本项目 PID、端口、地址和日志，仅管理明确归属于本项目的进程。
4. 手动启动和健康检查可纳入确认范围；开机自启、守护、计划任务、持续监控另外批准。
5. 长期固定入口再评估命名隧道和域名；账户、DNS 与费用另行确认，凭据不写入文档、代码或日志。

固定域名主要提高入口稳定性，不保证速度。Quick Tunnel 官方定位为测试开发用途，无可用性保证。

### D. 仍未达标时评估部署（另行决策）

- 若前端请求数已减少但公网 TTFB 仍高，再评估更接近用户的服务器或合规托管。
- 静态托管不等于完成迁移：跨域 API、Cookie、CSRF、上传和实时语音都需重新验证。
- 国内部署或简历/录音跨区域迁移前，核对备案、数据保护和授权条件，不在本轮直接迁移。
- 域名、服务器、套餐先列实际成本再批准，本次不购买资源。

## 4. 验收

功能必须满足：

- 登录/退出、过期会话、空间切换和企业隔离正常。
- 直接访问/刷新路由正常，按钮、筛选、上传和布局保留。
- 健康接口、未授权拒绝、CSRF 拒绝及 API 404 保持正确状态，不返回 SPA HTML。
- 合成文件覆盖上传确认、取消、响应中断恢复、去重与错误提示，不只以进度 100% 判断成功。
- 语音 WebSocket、录音上传、转写与断线恢复正常；不新增真实数据传输或付费模型调用。
- 无开发客户端、源码模块、热更新连接；无新增 MIME 错误、白屏及应用控制台错误。
- 桌面/手机截图、缓存更新、旧版本资源兼容通过检查。

| 性能项 | 目标与判断 |
| --- | --- |
| JS/CSS 请求数与依赖链 | 明显少于开发版，报告实际值，不盲目并为一个大包 |
| 公网 FCP/LCP 中位数 | 暂以同条件改善至少 30% 为目标而非保证，未达标报告瓶颈 |
| 暖缓存 | 重复传输下降，HTML 能更新，哈希缓存生效 |
| HTML/健康 API TTFB | 比较 P50/P95，不将构建收益当成网络延迟下降 |
| 上传/语音 | 无新增失败或重复记录，不牺牲业务换速度 |

样本不足、网络波动大于收益或功能失败时，不宣称通过；报告后再决定切换。

## 5. 风险与回退

| 风险 | 控制措施 |
| --- | --- |
| 代理破坏鉴权/上传/语音 | 独立端口先测，失败不切换 |
| 缓存版本不一致、旧分块 404 | HTML 重新验证、保留旧资源、完整版本回退 |
| 工作区有其他未提交改动 | 核对发布范围，不覆盖、重置或顺带提交 |
| 切换打断上传/面试 | 告知空闲窗口，确认无活跃上传和长连接后操作 |
| 临时地址变化 | 提供验证过的新链接，说明可能需重新登录 |
| 网络抵消收益 | 保留报告转入阶段 C/D，不靠反复重启碰运气 |

回退时将本项目隧道目标恢复至 Vite `127.0.0.1:5174`，必要时恢复旧构建/网关配置，检查登录及健康接口；重建临时隧道时提供新地址。不迁移、seed、清空数据库，不关闭其他项目服务。
