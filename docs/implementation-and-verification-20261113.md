## 二、已落地修改

### 1. 鉴权与公司隔离

- ModelScope 代理中的语音入口经 API 鉴权与计量，不再允许浏览器绕过网关直接进入语音服务。
- HTTP、WebSocket 使用公司 Schema 就绪约束，缺表、缺列、公司结构异常时拒绝，不回退 public 继续写入。
- Worker 健康端点安全处理畸形 Host，请求异常不能使进程退出。
- 保留普通用户与唯一系统管理员的权限负向测试；管理核对操作需要系统管理员、说明、确认及审计。
- 删除管理页已撤下审批/模型服务的写死提示；配置检查和健康异常不再显示为正常。

### 2. 简历并发与后台执行

- 简历导入使用跨公司共享队列台账与原子预留，任务及业务记录事务关联；活动中的重分析复用现有任务。
- 达到容量时返回 429 与 Retry-After；上传失败、取消及未知提交结果保留可恢复状态，不靠直接删文件补偿。
- Worker 平台预算与公司预算在数据库共享，多进程认领采用统一锁顺序、租约和心跳约束；丢失或过期租约不能继续提交结果。
- 默认平台执行预算 4、公司 2；验证时显式设置平台 3、公司 2，不修改用户运行配置。

### 3. 音频、转写与文件清理

- 整场转写加入持久任务、输入版本、幂等键、租约、心跳和片段 checkpoint；推理是否完成不确定时进入核对状态，不自动重复推理。
- PCM 采用逐段生成和释放，不一次保存整场解码数据；默认整场共享并发 2、单公司 1，可配置范围 1 至 16。
- 语音健康按实时、片段和复核能力区分；备用引擎正常不能冒充实时主引擎正常，健康探测不做收费推理。
- 音频写入与父面试删除串行化；回滚保留对象，删除成功后登记持久清理任务，已删除的父记录不能被在途写入复活。
- 简历与音频使用各自的存储类型和精确对象键；清理有租约、退避和引用保护。
- 新对象登记原存储位置指纹，配置切换或历史位置未知时阻止删除，不猜测当前位置。候选人已删除时，上传补偿仍可利用位置登记落清理任务。

### 4. 管理恢复入口

- 增加邮件发送未知、清理失败、转写未知、退款待核对的管理界面与接口。
- 邮件核对同步校验业务版本、Offer、申请和审计；不能凭旧版本核对覆盖当前业务。
- 退款采用查单退避，不在核对面板盲目再次退款；未知转写没有自动重试收费按钮。
- 弹窗支持说明、二次确认、初始焦点、Escape 和关闭后焦点还原；失败与更新冲突保留核对说明。

主要实现位于 API 的 recruiting、interviews、admin 模块，Worker 的 db 模块，以及 packages/object-storage 和前端 OperationalRecoveryPanel。新增数据库文件 0094 至 0098，仅在随机独立测试库应用。

## 四、安全发现与卫生处理

### 优先处理：仍有效凭据的明文副本

旧文件 tmp/releases/billing-minutes-20261110-134425/environment-before-release 存在模型密钥与带密码的数据库连接字符串签名。只在内存进行脱敏比对，确认其中的模型密钥与当前本地配置相同，且不是明显的合成占位符。报告与对话没有输出值。

全部 120 个可达历史提交的补丁扫描还发现 .env.codex-backup-20260920-150644 以及旧临时检查脚本中的数据库凭据字符串；历史备份可从对应 Git 对象读取，不能因当前目录不存在就认为已经消除。历史数据库密码未匹配当前本地配置，但是否在其他环境仍有效未知。扫描也命中了示例连接字符串、动态模板和测试私钥标记，签名命中不能全部认定为真实泄露。

当前 Git 跟踪文件未发现实际 .env/私钥/数据库 dump 文件。新增 Git 与容器忽略规则，防止运行日志、密钥、数据库备份及发布前后配置快照误纳入。没有擅自删除旧备份、改写历史或替换密钥。

建议先确认仓库、压缩包、备份、同步盘和历史分享范围；若这些内容曾离开可信环境，优先轮换模型密钥，按实际使用情况轮换数据库/SMTP/支付凭据，再确认备份与历史处理。不能把补一条忽略规则等同于撤销既有副本。

### 扫描范围与限制

脱敏扫描覆盖约 1083 个当前文本文件、约 1.59 万个构建/临时/日志文本和 120 个可达历史补丁。存在体积、二进制与特殊路径跳过，详细列表在 tmp/optimization-20261113-hygiene.json。历史检查关闭外部 diff 和文本转换，不执行仓库定义的转换器。签名扫描只针对常见密钥、私钥头和凭据 URL，不是完整个人信息识别，也不覆盖不可达 Git 对象或所有供应链内容。

定向检查未发现可据以定性恶意后门的证据；未发现业务源码中 eval/new Function、关闭 TLS 校验或 shell:true 的对应命中。此结论有范围，不能保证项目绝对干净。Python 依赖、容器基础镜像、模型权重和全部间接依赖没有完成来源级审计。

外连仍存在正常业务用途：模型收到简历/岗位/面试文本，OCR 收到文档或图片，语音服务收到音频，SMTP 收到邮件与收件人，支付渠道收到订单与核对字段，对象存储收到文件；身份验证与配置的渠道还可能调用各自服务。保留这些现有能力不等于本地存储的数据永不外传。临时 Tunnel 按要求保持原状，未擅自启用新的发送方或采集方。

## 五、备份恢复与部署

三个容量档都执行真实 pg_dump 和 pg_restore，恢复到另一个随机独立库，逐表行数及排序后的行 JSON SHA256 比对；本地对象逐文件 SHA256 比对，合成配置也逐项一致。

最大档恢复核对 643 张表、14311 行、1999 个对象，约 18.8 秒；这是小型合成数据恢复，不是生产恢复时间承诺。合成配置不含真实认证/加密密钥，未演练真实密钥保管和生产完整配置恢复。

0094_audio_objects_and_cleanup.sql、0095_full_audio_jobs.sql、0096_shared_analysis_budget.sql、0097_refund_reconciliation_backoff.sql、0098_storage_location_identity.sql 只应用于测试库。空库迁移、并发迁移和迁移失败回滚有测试；真实历史业务数据兼容性仍需业务库只读对账和经批准的升级演练。

禁止直接用新代码替换运行中的业务版本后碰运气启动。正式升级须另行确认：备份数据库与对象存储、受控保存实际密钥、暂停写入与 Worker、核对目标库及待迁移清单、迁移并核对公司结构、匹配版本启动 API/Worker、完成权限与业务冒烟后再放流。任一步失败先停新写入并保全诊断。

本轮没有业务迁移，因此不需要回滚业务数据库。未来升级后的恢复不能简单关闭公司 Schema 路由回 public；应停止新写入，按备份和增量对账恢复，明确处理备份后新增数据，不承诺无损回退。已有 docs/database-upgrades.md 中的 deploy:api/db:migrate 会执行目标库迁移，本轮没有运行这些发布命令。

## 六、尚未关闭的风险与未验收项目

1. 明文凭据副本及历史凭据须按实际传播范围处理；未经确认不删历史、不轮换生产凭据。
2. 文件物理写入之后、业务引用提交之前进程硬崩溃，仍可能留下孤儿对象。需要持久预登记或带保留期的盘点清单；不得按目录前缀直接批量删除。历史原存储位置未知的对象仍需人工核对。
3. 音频父记录锁跨物理存储 IO，S3 超时和长事务边界尚未进一步收紧；不要把本地存储测试外推到远端 S3 故障。压缩输入仍整份读入，不能称作全链路有界流式。
4. 路由顶层的持久转写/受管音频额外连接池生命周期尚未完全统一；长时间运行和频繁重建服务仍需持续验证。
5. 未知转写目前支持人工终止/核对，没有自动找回服务商结果；故意不自动重试收费推理。
6. 未执行 2 小时/8 小时持续负载、完整 CPU/磁盘/连接池/锁等待时序采样和所有业务模块真实浏览器闭环；当前不能给出生产承载规模或恢复时间保证。
7. 没有经授权、人工逐字标注的真实面试语音集，不能给出 CER、漏句或说话人准确率。已有 evaluate-transcription 只是文本比较工具，不替代真实识别。
8. SMTP 协议替身通过不证明真实送达；支付替身通过不证明真实通道可用。本轮按要求没有真实发信、收费推理、收退款或业务库迁移。
