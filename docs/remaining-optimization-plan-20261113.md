# 剩余问题优化与验收方案

日期：2026-11-13。状态：用户已确认按顺序实施；当前已落地文件一致性、资源回收及部分隔离验收与发布检查，仍有持续测试、完整浏览器闭环和待授权事项未关闭。逐项状态见 ordered-optimization-progress-20261113.md，本方案不等同于完成证明。

依据：implementation-and-verification-20261113.md，以及当前 managed-audio-storage.ts、object-cleanup.ts、persistent-full-audio.ts、full-audio.ts、routes.ts、server.ts 和对象存储接口。沿用前轮通过的测试作为回归基线，不重新把已有成果计为本轮新增。

## 一、结论与范围

剩余事项不是简单增加测试数量：优先关闭凭据副本风险和文件生命周期缺口，再统一资源回收，最后开展真实应用闭环与持续测试。真实服务验收和业务发布另设门槛，不与源码交付混为一谈。

沿用约束：

- 不真实发信、不调用收费服务、不真实收退款、不执行业务库迁移。
- 不优化临时 Tunnel、公网域名或证书；不替换现有模型、SMTP 和本地存储配置。
- 唯一系统管理员属于平台所有者；其余账号普通用户，不恢复多级审批或公司管理员。
- 公司继续采用独立 Schema；人员通过不可变随机编号关联，同名不合并。
- 不删除未知备份、不改写 Git 历史、不擅自轮换凭据，不回滚其他工作树修改。
- 可设计新增迁移并在随机独立测试库验证；迁移文件存在不代表批准业务升级。
- 已授权范围内按顺序实施；下述需单独确认的操作仍不执行。

## 二、问题优先级

| 优先级 | 剩余问题 | 处理目标 |
| --- | --- | --- |
| P0 | 当前有效密钥的旧副本、历史数据库凭据 | 明确传播与有效性范围，防止新增副本；轮换及历史清理单独批准 |
| P1 | 文件写入后、引用提交前硬崩溃留下孤儿 | 写入有持久意图、状态可恢复、删除有证据，不误删有效或迟到对象 |
| P1 | 音频写入与清理将物理 IO 放进数据库事务 | 将慢 IO 移出持锁事务，同时保住删除与提交引用的竞态约束 |
| P1 | 路由顶层连接池与后台服务生命周期不统一 | 每个资源有归属，启动失败、重复创建、关闭均可回收 |
| P1 | 压缩整场音频仍整份读入内存 | 端到端背压、临时磁盘额度、子进程取消和整机资源测量 |
| P1 | 全业务浏览器闭环与持续负载未覆盖 | 用真实本机应用和隔离数据验证，不用界面夹具替代数据链路 |
| P2 | 未知转写不能自动找回结果 | 支持有能力服务商的只读核对；不支持时继续保留未知，不重新提交推理 |
| P2 | 真实语音、邮件和支付尚未验收 | 分开建立可测项与授权门槛，禁止将模拟通过描述为真实可用 |
| P2 | 发布兼容与实际配置恢复未验收 | 完成隔离演练和发布清单；不自动升级业务实例 |

P0 表示需优先处置，不代表已经确认外部泄露或存在恶意行为。

## 三、第一阶段：凭据处置准备与文件一致性

### 3.1 凭据与代码卫生

1. 产出脱敏清单：位置、凭据类别、是否与当前值相同、是否进入可达历史、是否曾打包或同步；不输出密钥或可离线猜测的密码摘要。
2. 核对受版本控制的文件、构建上下文、发布脚本、调试输出和备份生成入口，阻止后续把实际配置写入日志或可分享产物。
3. 凭据检测只扫描，不执行仓库脚本；报告限制访问，并记录跳过项和误报确认结果。不把所有签名命中定性为泄露。
4. 形成轮换顺序、依赖服务、验证办法及旧凭据撤销步骤。新凭据先受控保存，验证后撤销旧值；发生实际泄露时不把恢复已泄露旧值作为回退手段。
5. 历史清理、备份删除、服务商撤销凭据均等待明确授权。添加忽略规则不能算风险关闭。
6. 补充 Python 依赖、容器镜像、模型加载配置与来源清单；记录是否启用执行远程代码的能力，无法验证的部分保留风险状态，不擅自加载不可信权重。

验收：新增合成凭据能触发阻断，报告不回显秘密；真实凭据发现逐条有处置状态。未经轮换或确认不再有效的项目，不标记关闭。

### 3.2 对象写入状态机

优先复用已有对象登记、位置指纹和清理任务，确需新字段时增加新迁移，不修改已应用的历史迁移。

- 写入前短事务登记意图，记录公司、父业务编号、存储用途、位置指纹、对象键、内容版本、尝试编号、租约和时间。
- 建议状态：已预登记 -> 写入中 -> 待绑定 -> 已绑定；失败或父记录删除后进入待核对/待清理，再进入清理中 -> 已删除。
- 每次写入使用不可变、带唯一尝试编号的对象键；业务指针更新到新版本，不覆盖仍可能被旧请求访问或删除的键。
- 提交预登记后执行物理 IO，不在整个上传期间持有父记录锁。上传完成后开启短事务，重新核验父记录、公司、版本和租约，再提交引用。
- 删除父记录时原子阻止后续引用绑定，记录清理意图；迟到上传不能复活业务记录。
- 清理先在短事务中锁定对象状态、检查引用、标记清理中；此后绑定必须拒绝。物理删除移出事务，完成后再条件更新。
- 对上传超时、提交响应丢失、删除结果不明分别保留可核对状态。客户端超时不代表远端停止，不能仅凭租约过期立即认定对象不存在或安全可删。
- 对仍可能迟到完成的写入保留墓碑和重复盘点；只有对象键不复用、写入窗口已关闭、引用再次核对通过，才能收敛到终态。无服务端取消保证时明确保留不确定性。

### 3.3 孤儿盘点与历史文件

- 默认仅生成报告，不删除；扫描限定显式配置的存储位置和对象命名范围，分批、限速，避免占满内存。
- 盘点区分：有引用、已知未绑定意图、历史未知对象、位置不匹配、大小或校验异常；跨公司或结构缺失时停止相关删除判断。
- 对已确认的正常业务删除仍走既有清理策略；仅对孤儿候选建议设置可配置保留期，初始建议 7 天，最终按业务要求确认，不悄悄延长用户正常删除期限。
- 删除前重新验证公司、位置、对象版本、引用和已确认的清理清单。历史未知位置只列清单，不猜测映射、不按前缀批删；不新增业务审批层级。
- 本地处理必须核验真实目标路径，防目录穿越与符号链接/目录联接越界；测试清理严格限定本轮临时目录。

阶段验收：在预登记、物理写入、引用提交、父记录删除、物理清理等节点分别硬终止子进程并重启；无有效引用误删、无删除复活、无旧任务删除新版本，未绑定对象最终有登记或明确待核对状态。涵盖超时后迟到写入和存储位置切换。

## 四、第二阶段：资源生命周期与长音频

### 4.1 连接池与服务生命周期

- 将路由模块导入时创建的音频相关服务逐步改为应用初始化时注入，不进行与本问题无关的大范围重构。
- 明确请求服务、任务轮询和独立租约心跳的池归属；仅资源所有者关闭连接池，避免共享池被重复关闭。
- 停止流程统一为：停止新请求和任务认领 -> 等待在途工作 -> 到达上限则取消 -> 回收子进程与临时文件 -> 关闭自有连接池。
- 覆盖端口绑定失败、初始化中途失败、活动 WebSocket、重复关闭和正在执行清理/转写时关闭；关闭失败必须可见，不一概吞掉。
- 统一统计连接总数、空闲数、等待数、获取耗时和超时；保持心跳资源不被长任务耗尽，不宣称一个池适合全部职责。

验收：同进程连续创建和关闭应用至少 50 次，数据库连接及定时器不逐轮增长；有在途任务的关闭行为符合约定，端口失败不留下后台轮询。

### 4.2 从整份 Buffer 改为有界处理

- 给对象存储增加可取消的流式读取/写入能力，保留原小对象接口，避免一次迫使所有调用方迁移。
- 整场音频的生成、缓存、下载和转写分别核对，不仅改分段函数。将完整压缩文件在接口间反复传递改为受控临时文件或流。
- ffmpeg 输入输出有背压，PCM 逐段释放；统一取消信号、执行期限和子进程回收。输出错误不得被当成成功空结果。
- 限制真实读取字节数、时长、片段数、单任务临时磁盘和总并发；不能只信文件声明大小或 Content-Length。
- 临时文件登记归属，成功、失败、取消均清理；进程崩溃后的残留通过本应用专用目录及保留期盘点，禁止扫删系统临时目录。
- 在本地 S3 协议替身注入慢响应、中断、半写入和删除超时，验证数据库锁等待不随存储延迟持续增长。

验收：两份不同的两小时合成录音并发处理，监测 Node、全部 ffmpeg 子进程、临时磁盘、句柄与连接池；增加时长时内存不按完整 PCM 或完整压缩文件线性累积。数值预算先按机器资源确定，必须测前固定，不能根据结果临时放宽。

### 4.3 未知转写核对

- 仅当现有服务商支持只读查结果时，登记服务商任务编号、输入指纹、调用意图及计费关联，并提供查询适配器。
- 不假定所有提供方支持查询；响应丢失且无任务编号时允许继续未知，不通过重新提交来冒充查单。
- 结果找回前核验公司、输入版本、取消/删除状态和任务版本；旧任务不得覆盖新结果，也不重复记账。
- 不支持查询的引擎保留人工核对/终止，并说明终止不等于服务商退款或从未收费。
- 管理核对保留唯一管理员、说明、审计和并发版本检查；不得扩大普通用户权限。

验收：用提供方替身验证可查回、无任务号、重复返回、旧输入、删除后返回、核对冲突；任何未知分支都不自动再次发起推理。真实查询也不在本轮默认执行。

## 五、第三阶段：业务闭环、语音链路与持续测试

### 5.1 真实本机应用闭环

测试浏览器连接隔离 API、Worker、数据库与对象存储；模型、SMTP、支付为本地替身。阻断未列入允许名单的外部网络，绝不继承真实凭据作为默认值。

| 流程 | 重点场景与断言 |
| --- | --- |
| 账号与权限 | 登录、过期、退出、公司切换、普通用户访问管理入口拒绝；旧页面写入不能串公司 |
| 公司与人员 | 同名公司/同名人员、随机编号、关联数据归属；创建公司不得产生新系统管理员 |
| 岗位与简历 | 批量导入、重复点击、取消、丢响应恢复、原文读取、结果更新、删除关联数据 |
| 面试 | 准备、开始、录音、断连恢复、结束、回放、片段与整场转写、总结、删除竞态 |
| Offer 与入职材料 | 创建、编辑、版本冲突、撤回、附件权限、已完成后补充、删除与审计回滚 |
| 邮件 | 本地收信服务核对收件人、附件及内容；拒信、超时、发送未知，不重复投递 |
| 充值订阅 | 替身支付成功/失败/回调重放、产品改版、取消、退款核对、额度与权益一致 |
| 异常核对 | 邮件/转写/文件/退款核对，多标签页冲突，普通用户不可见、不可调用 |

对有现有实现的额度、工单与账号设置补充闭环；未实现或已隐藏功能单独标明，不为了测试通过重新开放审批。

证据包含浏览器截图、请求标识、独立库对账与本地文件结果。密码、完整录音、简历正文、邮件正文不进入公共日志或通用截图。

### 5.2 语音分层诊断

第一层，无真实外部调用即可执行：用合成音频和可重复本地测试片段检查采样率、声道、编码、源音轨、分片边界、静音、断线重连、乱序、重复片段、时间戳及最终持久化。逐环节比对预期长度和缺片，保留原始识别与后处理文本的区分，避免语义修正掩盖漏字。

第二层，需要授权样本：建议准备不少于 30 段、累计不少于 60 分钟的脱敏真实面试录音，覆盖安静、噪声、口音、中英混合、专业术语与双人重叠。按说话人/场次分开调参与验收集，防止测试样本泄漏到调参。

若现有引擎能确认在本机离线运行且不计费，可在明确样本授权后验收；不能确定费用或存在外发时不调用。不是为了绕过限制新开收费实例或擅自下载模型。

指标：加权字符错误率 CER、关键姓名/数字/术语正确率、漏句率、重复率、首字/最终结果延迟；仅在功能有说话人输出时验收说话人归属。原始结果和后处理结果分开公布，识别完全失败计入，不静默排除困难样本。

阈值通过独立基线和业务容忍度测前确认；初期至少要求修复目标场景改善、其他场景无明显回退，不能只给一个平均准确率。未取得真实样本时只交付链路测试，准确率保持未验收。

### 5.3 分档与长时间测试

- 先重跑 60/500/2000 份合成导入档位，再混合简历、音频、删除、核对和公司切换，不只测单接口。
- 先执行 30 分钟预检，通过后运行 2 小时持续负载，最后在明确本机资源窗口内运行 8 小时混合负载；依次执行，失败先分析修复。
- 全部使用随机独立库和临时目录，禁止落到业务连接；测试停止不影响用户原服务。
- 记录端到端 P50/P95/P99、失败率、积压与排空时间、租约回收、重复有效提交、公司公平性、进程树 CPU/RSS、磁盘、连接池、锁等待与临时文件残留。
- 每次只注入一个故障，覆盖 API/Worker 终止、实际租约自然到期、数据库短断连、本地存储慢响应/磁盘额度耗尽、音频进程超时与回调重复。主动改时间模拟与自然到期分别报告。
- 测前固定资源上限、错误率阈值和停止条件；触发磁盘余量、内存、业务隔离等安全门槛立即停止生成负载并保存证据。

验收：受理数与最终业务/任务结果精确对账；无跨公司数据、错删、重复有效执行或权益重复入账；故障后可排空。内存和连接无持续爬升，其他数值依据测前预算判断。长期测试未跑完不写成通过，不以定时任务替代本轮执行。

## 六、第四阶段：发布准备与待授权验收

### 6.1 无业务变更的发布准备

- 生成待迁移清单、影响表、锁与索引风险、公司结构前置条件，以及新旧服务兼容矩阵。
- 在独立历史结构夹具中演练空库、旧结构、多公司差异、并发升级、失败恢复；若须用脱敏业务快照，另行确认复制范围与保管方式。
- 通过受控模拟加密密钥验证恢复步骤及密钥缺失时明确失败，不把合成配置恢复冒充真实配置已恢复。
- 备份清单区分数据库、文件、密钥和配置。记录备份之后的增量处理与恢复步骤，不承诺简单降级或零丢失。
- 准备启动前只读门禁，缺必要结构或存储不匹配时明确拒绝启动；普通重启不自动迁移，不能关闭 Schema 路由回公共表绕过门禁。
- 本轮只产出检查工具和升级/恢复说明，不执行 deploy:api、db:migrate 或新版业务切换。

### 6.2 必须单独确认的事项

| 事项 | 确认内容 | 未确认时处理 |
| --- | --- | --- |
| 凭据轮换与历史处置 | 服务商、凭据范围、分享范围、备份保留、协作仓库影响 | 保留副本与风险记录，不撤销或删历史 |
| 历史未知文件清理 | 精确位置、对象清单、引用证据、保留期 | 只出盘点报告 |
| 真实语音验收 | 样本授权、脱敏、保存期限、端点是否本机且免费 | 不读取真实录音作推理、不外发 |
| 真实邮件 | 专用测试收件人、发送上限与时间 | 只测本地收信服务 |
| 收费模型或服务 | 提供方、次数、费用上限、输入范围 | 默认阻断 |
| 真实收退款 | 渠道、金额、次数与对账责任 | 只用替身 |
| 业务库读取/快照 | 目标库、只读方式、查询范围、敏感数据保管 | 使用合成/历史结构夹具 |
| 业务迁移与发布 | 备份、停写窗口、迁移范围、失败处置和恢复责任 | 不迁移、不切换 |

## 七、交付与完成判定

按第一至第四阶段推进；凭据传播核实可与源码工作并行，资源修复完成后才运行长期混合负载。每阶段保留问题编号、改动文件、迁移影响、测试命令、退出码、报告位置和未验收项。

代码阶段完成必须同时满足：

1. 文件状态机及全部竞态故障测试通过，没有把未知状态直接当作可删或可重试。
2. 自有连接池、子进程、轮询和临时文件可回收，长音频资源测量包含子进程。
3. 主要业务真实本机浏览器闭环、持续测试和原有全量回归通过，失败记录及修复原因保留。
4. 安全扫描报告有范围、有误报、有未关闭项，未回显秘密，未擅自清理历史。
5. 对真实语音、SMTP、支付、实际备份恢复与业务部署分别标记未验收/已验收，不能互相替代。

最终提供三张独立状态表：源码完成情况、测试验收情况、业务部署情况。只满足代码阶段时可以交付代码，不宣布已经可直接生产使用。
