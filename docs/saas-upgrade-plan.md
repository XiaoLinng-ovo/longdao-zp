# SmartRecruit Pro 企业 SaaS 分步升级与验收

更新时间：2026-10-13

## 已确认的产品边界

- 日常流程：直接创建岗位 / 岗位说明书与 JD → 简历筛选 → 面试 → 录用及薪资审批 → Offer → 入职。
- 停用招聘需求申请审批的客户入口，不删除历史记录。
- 保留录用审批、审批任务、Offer 版本与审批状态校验；不得因需求功能停用删除公共审批服务。
- 企业所有权、成员管理身份、招聘业务角色和审批任务授权是不同概念。
- 本文的商业化能力是后续实施计划，不表示已全部完成。

## 执行约定

原约定为分步交付并由用户确认。2026-10-12 用户明确改为连续推进：每阶段自测通过后自动继续，不再等待逐步确认；遇到无法自行解决的技术阻碍、缺失商户/外部服务信息或未确定的商业规则时停止并说明。仍说明完成项、验证结果、未完成边界和可选人工测试方法。
不自动提交或推送、不重置账号、不重新初始化数据库、不清空历史业务数据。

## 第 1 步：业务入口与角色说明整理（已交付）

- 使用同一前端功能标记约束需求列表、详情和需求审批设置的导航与直接访问。
- 功能关闭时，已登录且选定企业的用户访问旧网址，跳转岗位管理并显示说明。
- 登录校验和企业选择仍先于功能跳转。
- 岗位导航分类调整为“岗位招聘”。
- “企业审批设置”精确命名为“需求审批设置”，随需求功能关闭；它不是录用审批配置，不将原配置改名冒充 Offer 配置。
- “审批人”在成员邀请、成员列表与顶部身份中显示为“录用审批人”；接口角色码 approver 不变。
- 成员管理底部提供默认折叠的角色说明，不遮挡表单。
- 现有角色、已有成员和 Offer 工作流不变。角色说明不是新权限引擎。

### 人工验收

1. 登录并选择企业：左侧没有需求管理、需求审批设置，仍有岗位管理、录用审批与 Offer。
2. 访问 /requisitions、/requisitions/任意历史ID、/enterprise/approval-settings：跳转 /jobs 并解释需求审批已停用、Offer 保留。
3. 岗位管理点击“新建岗位”：无需关联需求即可填写岗位。
4. 企业工作空间展开成员与邀请：业务角色仍可选择“录用审批人”；底部说明默认折叠，可手动展开。
5. 打开已有 Offer：原审批、查看及编辑权限和流程不因本步改变。本步自动测试只证明路由未误拦截，实际审批动作需使用有权限的账号及测试 Offer 验证。

### 范围与安全边界

这是前端入口一致性整理，不是后端 API 下线或完整多租户安全交付。历史需求 API、公共审批服务与数据库保持兼容。后续应独立评估需求写接口的关闭策略、历史只读访问和钉钉回调，不可仅靠隐藏菜单认定安全。

前端 VITE_RECRUITMENT_REQUESTS_ENABLED 默认为关闭。显式设为 true 后重启开发服务器或重新构建 Web 可恢复历史入口；恢复时企业管理权限校验仍有效。生产是否保留该开关需在上线配置审计中确定。
