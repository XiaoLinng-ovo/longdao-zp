# 完整测试与优化方案

日期：2026-11-13。状态：用户已批准排除真实发信、收费调用、真实收退款和业务库迁移后的实施范围。本轮已落地主要源码修改及隔离回归，仍有验收与安全待办；详见同目录 implementation-and-verification-20261113.md，不代表全部发布门槛通过。

## 一、目标与边界

目标是验证业务是否正确、公司数据是否隔离、并发与故障能否恢复、真实外部服务是否可用，并对发现的问题逐项修复与回归。

- 唯一系统管理员属于平台所有者，由不可变账号编号绑定；其他账号均为普通用户，不恢复企业管理员或多级审批。
- 沿用现有模型、SMTP 和本地存储配置。公司隔离采用同一 PostgreSQL 内独立 Schema，不改成独立物理数据库。
- 同名公司、账号、候选人分别建档，使用不可变唯一标识关联，姓名不能作为主键或默认合并依据。
- 临时 Tunnel、公网域名、证书和公网部署拓扑暂不优化；应用自身的鉴权绕过仍属于修复范围。
- 不撤销既有未提交修改，不擅自删除日志、备份或临时文件；先形成清单再确认清理。
- 本方案不执行业务库迁移、修改运行配置、真实发信、收费模型调用或真实收退款。此类操作另行明确对象、次数、费用和恢复方式。

## 三、第一阶段：已确认缺陷修复

以下问题来自前轮代码审查，不代表已在当前业务部署中全部触发。优先处理鉴权入口，其余修复完成后再提高并发规模。

| 问题 | 优化设计 | 必须通过的验证 |
| --- | --- | --- |
| 备用 ModelScope 部署直连语音服务 | 浏览器语音入口统一经过 API 的会话、公司、额度与并发校验；核查其他代理模板 | 未登录、跨公司、额度不足均拒绝；合法连接计量正确；代理配置不能绕过网关 |
| Worker 健康端点畸形 Host 可导致退出 | 安全解析请求，异常请求返回错误且不影响进程 | 独立子进程发送畸形 Host、路径及连续请求；进程存活且后续健康检查成功 |
| 流式语音缺少公司结构就绪检查 | HTTP、WebSocket、Worker 共用公司注册和结构检查约束；缺失时拒绝 | 删除测试 Schema 或表，同时保留 public 历史表；必须拒绝且不创建计费租约、不回退处理 |
| 简历全局积压限制实际受单公司上下文影响 | 区分平台、公司、进程限制；使用共享台账和事务原子预留，不能只先汇总再写入 | 多公司、多 API 同时冲击上限；不超卖、不串公司；失败、取消和崩溃后额度可回收 |
| 删除面试未清理音频及缓存 | 提交事务时登记带存储类型、位置的持久清理清单；隔离简历与音频存储 | 回滚不删文件；提交后最终清理；在途上传与转写不能复活已删数据；共享引用受保护 |
| 语音健康状态与实际主引擎不一致 | 按实时、片段、整段和复核能力分别报告配置与可达状态；有超时与短时缓存 | 主引擎故障而备用引擎存活时不误报实时可用；健康探测不触发收费推理 |

文件清理还需先核对存储清单与数据库引用，对孤儿对象设置保留期和人工确认，不按未经核验的路径前缀批量删除。Schema 缺失存在回退风险，不据此宣称已经发生跨公司泄露。

阶段交付：缺陷复现、修复、正反向回归、代理模板检查和剩余限制说明。

## 四、第二阶段：并发、任务恢复与运维

### 4.1 持久任务与资源预算

- 整段音频转写从进程内状态升级为持久任务，复用现有 PostgreSQL 任务模式；记录业务幂等键、输入版本、状态、重试次数、租约及心跳。
- 以原子认领、过期回收和重试上限支持多 Worker 与进程重启；旧输入的处理结果不能覆盖新版本。
- 平台和公司预算跨进程共享，进程内信号量只控制本机资源；加入公平调度，验证大公司不能长期饿死其他公司。
- 音频分段采用有界缓冲和逐段释放，不一次持有整场 PCM；以长录音和多任务测量内存峰值后确定默认并发。
- 外部调用超时可能已经产生费用或完成发送；区分确定失败与结果未知，不能把自动重试等同于不会重复计费。

### 4.2 可操作的恢复入口

- 为邮件未知状态增加仅唯一系统管理员可用的核对界面，展示脱敏业务标识、Message-ID、时间、状态和操作审计；必须核实后才能恢复。
- SMTP 接受不等于最终送达，不承诺协议层严格恰好一次；核对后恢复时邮件、Offer、申请状态和审计必须一致。
- 清理任务、退款任务采用有上限的指数退避和随机抖动，展示失败原因、下次尝试时间和人工处理入口；告警先落到本地管理状态，不擅自启用新的外发通知。
- 保留现有配置，只新增必要的显式选项与安全默认值；不为上述任务额外引入无关基础设施。

阶段交付：多进程任务回归、资源基线、崩溃恢复证据及管理员恢复操作说明。

## 五、第三阶段：全业务测试矩阵

各模块均覆盖正常、边界、异常、权限、并发、幂等、数据一致性；测试权限应以当前普通用户模型为准，不重新引入审批。

| 模块 | 关键场景与验收点 |
| --- | --- |
| 注册、登录与会话 | 会话过期、退出、禁用账号、CSRF；普通用户直调管理员接口被拒绝；历史角色及运营授权不能提权 |
| 公司与账号隔离 | 两家同名公司、同名人员、不同随机编号；切换公司、旧标签页、伪造对象 ID、下载与导出、连接池复用均不能串数据 |
| 岗位与申请 | 创建、编辑、关闭、投递、状态流转、重复提交、失效岗位；列表和详情一致 |
| 简历导入 | 单份、批量、重名、重复内容、损坏、超限、伪造扩展名、扫描件；失败可定位并重试，取消后不继续写入 |
| 后台解析与匹配 | OCR 或模型超时、限流、畸形响应、数据库提交失败、任务抢占；关联与额度不重复，错误不伪装成功 |
| 面试与语音 | 双音轨、麦克风拒绝、断线重连、重复片段、乱序、长录音、角色不明；时间轴可核对，不把不确定识别直接当事实评分 |
| Offer 与邮件 | 版本编辑、附件、正文净化、并发发送、明确拒收、发送后提交失败、未知状态核对；同业务版本仅一次有效发送预留 |
| 入职与材料 | 企业归属、父记录锁、重复材料编号、并发更新、审计回滚；取消或未到岗不可修改，已完成允许补充，无审批依赖 |
| 充值与订阅 | 验签、金额币种、重复及乱序通知、权益发放、续费边界、取消与付款竞争、历史退款、重复退款与查单恢复 |
| 删除与存储 | 候选人和简历关联策略、面试音频、共享引用、事务回滚、在途任务；数据库与文件最终一致，受引用限制的删除明确提示 |
| 查询、报表与导出 | 分页、筛选、排序、时区、空值、大数据量、公司隔离、表格公式注入；汇总与明细核对 |
| 平台配置与渠道 | 仅唯一管理员可改平台设置；普通用户无隐藏提权入口；未实现招聘渠道明确不可用，不能显示配置成功即支持发布 |
| 浏览器交互 | 主要流程实际操作，刷新、后退、重复点击、网络错误、桌面和移动布局；进度和失败状态可理解，无明显遮挡 |

每个主流程至少完成一次浏览器到 API、Worker、数据库、存储的闭环核对，不能仅逐接口返回成功。涉及发送或支付的闭环先使用协议替身和沙箱。

### 5.1 真实语音与 OCR 验收

语音先建立有授权且人工逐字校对的样本集：建议至少 30 段、合计 60 分钟短样本，另加 2 场各 30 分钟双音轨面试。覆盖近讲、远场、口音、噪声、抢话和专业术语，保留完全失败样本。样本不足时明确覆盖缺口，不虚构真实准确率。

分别比较实时、片段、整段及复核输出，指标包括中文字符错误率 CER、漏句、角色归属、时间偏差、首字延迟、终稿延迟与关键事实错误。CER 按参考字符数加权，可超过 100%，不能简单改写为准确率；归一化规则、人工答案版本与各场景分母需固定。

建议初始目标：安静普通话 CER 不高于 10%、普通会议不高于 20%、可判定片段的角色正确率不低于 95%。这些是待样本基线确认的验收目标，不是已实现的承诺；困难分组单独报告，不能被总体均值掩盖。金额、日期、姓名、否定词等错误需逐项复核。

先定位采集权限、采样率、重采样、音轨混合、分段边界、传输重连和引擎配置，再决定优化顺序；不默认通过更换用户模型解决。评分和总结使用同一录音的人工校对文本作对照，检查识别错误是否被放大为候选人结论。

OCR 采用 PDF、DOCX、图片和扫描件的人工标注样本，单列文本提取失败率、姓名/电话/邮箱/工作经历等字段正确率及低置信度处理。关键字段可先提议 98% 为目标，须明确字段分母并根据真实样本确认；错误允许人工修正，不能静默覆盖已有资料。

### 5.2 真实 SMTP 与支付验收

- SMTP 先用本机协议服务器验证认证、TLS 配置、中文主题、纯文本与 HTML、附件、拒收及断连，再向批准的测试邮箱少量发送。
- 真实验收记录服务商受理、实际收件、垃圾箱、附件可读性和耗时；授权码、发件身份及配额分别核验。没有实际收件证据时，只能说协议发送通过。
- 发送超时后以 Message-ID 查询服务商日志或人工核对，验证系统不会盲目自动重发；真实服务商日志不具备时记录恢复限制。
- 支付优先沙箱验证通知与查单交叉核对、金额币种、权益和退款状态。真实小额收退款需另行批准金额、次数、账号与费用，不能将替身通过当作正式支付可用。

### 5.3 并发与容量测试

| 档位 | 合成数据与客户端提交并发 | 服务拓扑 |
| --- | --- | --- |
| 基础 | 3 公司，每家 20 份，10 个并发提交 | 单 API、单 Worker |
| 常规 | 5 公司合计 500 份，20/50 个并发提交 | 两个 API，1/2 个 Worker 对比 |
| 边界 | 10 公司合计 2000 份，100 个并发提交 | 两个 API、三个 Worker；含热点公司 |
| 持续 | 替身服务 2 小时持续导入、8 小时低负载运行 | 仅独立环境，检查积压与资源增长 |

上述为起始实验规模，按本机可用资源下调；不是项目已支持的容量声明。客户端提交并发不等于模型推理并发。真实 OCR/模型从 1、2、4 路逐级测量，设置调用与费用上限，出现资源告警即停止加压，不能挤占用户正在使用的服务。

记录排队时间、吞吐量、各阶段耗时及 P50/P95/P99、429/5xx、内存、CPU、磁盘、连接池、锁等待、租约回收和每公司公平性。计数分别核对提交、受理、拒绝、成功、失败、取消、待处理及重复请求，不能凭界面数量判断无丢失。

建议基础和常规档下非推理列表/状态接口 P95 不超过 2 秒，非预期 5xx 为零；跨公司、错删、重复权益和重复有效任务必须为零。429 是明确的背压结果，不能计为成功，但应提供可重试信息并保持幂等。模型耗时与队列等待先取基线再定服务目标，不承诺固定几秒处理完。资源限额、恢复时限和观测时长须写入测试配置。

### 5.4 故障注入

在任务认领后、外部调用前后、事务提交前后终止独立进程，并注入数据库断连、存储不可写、磁盘不足、OCR/模型超时与限流、SMTP 断连及支付通知乱序。每种故障验证任务、业务状态、额度、审计、文件和租约能否一致恢复。

确定失败按受限重试恢复；结果未知进入核对流程。不能用重启后界面恢复正常代替数据库与外部结果核对。禁止在业务环境制造磁盘写满或主动中断现有服务。

## 六、第四阶段：工程安全、清理与发布演练

### 6.1 安全与代码卫生

- 先形成文件用途与引用清单，区分源码、构建产物、模型调试脚本、日志、截图、补丁、备份和未知文件；确认后再清理，保留必要审计与故障证据。
- 扫描当前工作树、Git 跟踪与历史、构建上下文、前端产物和日志中的密钥及个人信息；若发现真实泄露，先轮换密钥，再处理文件与历史，不把删除当前文件当作已消除泄露。
- 核查 Node、Python、容器基础镜像及模型来源、锁文件、安装脚本、动态执行和下载行为；按风险定向升级并回归，不盲目全量升级。已知漏洞审计为零不能证明不存在恶意依赖。
- 列出模型、OCR、SMTP、支付及渠道的外连接收方、触发条件和传输字段；检查日志脱敏、调试开关及默认关闭策略。外部模型调用不得向无关接收方发送完整资料。
- 检查上传类型与体积、解压及解析资源上限、路径穿越、对象键归属、下载鉴权、命令参数与 SQL 参数化；验证模型输出和简历中的提示注入不能变成越权操作或可执行命令。
- 检查配置型 URL 的访问边界、重定向与凭据泄露风险，以及 HTML/表格导出净化；不因系统使用本地存储就认定数据不会外传。
- 保持招聘渠道占位功能明确不可用，不擅自接入第三方抓取；清理已撤下审批与模型共享功能的旧入口和过时断言，但保留权限回归测试。

结论分为确定缺陷、潜在风险、未验证项和未发现异常；不能以静态扫描给出绝对无后门、绝对干净的保证。

### 6.2 数据升级与恢复演练

- 独立测试库分别验证空库安装和历史版本升级，检查迁移顺序、公司结构清单、索引、约束与 API/Worker 同步切换。
- 业务库只读核对旧 public 数据与公司 Schema 的数量、归属、引用、任务状态、权益及迁移记录；只读核对也需控制负载和输出脱敏。
- 发现历史数据差异先设计增量补齐与对账，不直接重跑导入或覆盖公司数据。正式迁移需确认备份、停写窗口和执行范围。
- 备份覆盖数据库、本地对象存储、配置及必要的加密/认证密钥，并在隔离环境实际恢复；备份本身受限访问，不能只验证备份文件存在。
- 公司 Schema 已有新写入时，不允许只关闭开关回旧 public；回退须采用经过演练的增量迁移或完整恢复，并核对期间新增数据。
- 演练记录恢复耗时、允许的数据缺口、失败回滚路径和人工步骤；恢复目标在业务窗口与数据量确定后确认，不能未经演练承诺零数据丢失。

阶段交付：安全发现及处理清单、经确认的文件清理清单、升级与备份恢复报告、发布和回退检查表。
