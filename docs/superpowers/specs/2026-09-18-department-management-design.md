# 部门管理与招聘需求下拉选择设计

## 目标

管理员可以新增、改名和停用部门；招聘需求新建/编辑页面只从后端读取启用部门并用下拉框选择。部门编码保持稳定，历史招聘数据不因改名或停用而丢失。

## 方案

- PostgreSQL `departments` 继续作为唯一部门事实源，使用已有 `id/code/name/is_active` 字段。
- 登录用户通过 `GET /api/v1/departments` 获取启用部门；管理员通过 `GET /api/v1/admin/departments` 获取全部部门。
- 管理员通过 `POST /api/v1/admin/departments` 新增部门，通过 `PATCH /api/v1/admin/departments/:id` 修改名称或 `isActive`。
- 部门 `code` 创建后不可修改，避免破坏用户、岗位、招聘需求和数据范围引用；名称可修改。
- 停用采用软停用，不物理删除。停用部门从新建需求下拉框移除，但历史记录继续展示。
- 管理员页面增加部门管理表和新增表单；招聘需求新建、编辑页面动态加载下拉选项。

## 错误与权限

- 部门列表要求登录；管理员写操作要求 `admin` 或 `hr_admin`。
- code/name 为空、code 重复、部门不存在分别返回标准校验/冲突/未找到错误。
- 创建或编辑招聘需求仍由后端校验部门 code 存在，前端下拉只是可用性提升。
