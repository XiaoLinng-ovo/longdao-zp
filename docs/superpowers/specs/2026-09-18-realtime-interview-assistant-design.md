# 现场实时 AI 面试辅助设计

## 目标

在已有面试安排和反馈闭环上，增加现场面试辅助：一次启动面试后持续采集麦克风音频，实时转写并按说话人分段，在候选人回答形成稳定片段后调用已配置的 OpenAI 兼容模型进行分析，生成证据、评分建议和下一道题。AI 只提供可追溯建议，不自动淘汰、录用或修改申请状态。

## 设计原则

- 采用成熟语音管线的分层逻辑：VAD/ASR 负责时间段和文字，speaker diarization 负责匿名 `speaker_0`/`speaker_1`，招聘流程状态和语义分类负责映射“面试官/候选人”。
- 第一版只支持现场单机麦克风，不采集系统声音、不接钉钉会议音轨、不要求预先录制声纹。
- 面试官开场是角色初始化信号，但不是唯一依据；提问/回答语义、轮次状态和说话人连续性共同决定角色置信度。
- 原始音频、转写片段、角色映射、人工修正、AI 分析和问题版本全部持久化，低置信度内容不进入自动评分。
- 大模型调用只在稳定回答片段完成后进行，模型失败时保留转写并允许重试，不伪造分析结果。

## 运行流程

```text
创建/打开面试 -> 启动面试会话 -> 麦克风授权 -> VAD/ASR 流式转写
-> speaker diarization 生成匿名说话人 -> 角色状态机映射
-> 候选人回答片段结束 -> 结构化 LLM 分析
-> 保存分析结果 -> 显示追问/下一题 -> 面试官确认并结束
```

会话开始时处于 `interviewer_opening`；检测到首个稳定发言人后暂映射为面试官。识别到问题后进入 `candidate_answering`，停顿达到切段阈值或服务端确认最终片段后提交分析。候选人反问、抢话和多人重叠会降低置信度，但不会交换已确认的角色；面试官可在时间线中修正片段角色。

## 数据边界

后端新增面试会话、音频片段/对象地址、转写片段、说话人映射、问题、回答分析和修正记录。每条 AI 分析记录保存模型标识、提示版本、输入片段 ID、结构化输出、置信度和创建时间。简历全文和密钥不会写入提示日志。

## 前端体验

面试详情页增加“开始 AI 面试”入口。面试室显示录音状态、当前问题、带角色标签的实时字幕、回答分析、建议追问和完整时间线。默认自动切段；面试官只需要暂停/恢复、忽略片段、修正角色和确认下一题。浏览器不支持麦克风或用户拒绝授权时，保留人工反馈流程并明确显示原因。

## 外部服务边界

语音服务通过受控的服务端适配器接入 FunASR 兼容部署；不在浏览器直接访问 ASR 或大模型。大模型只通过现有 OpenAI 兼容客户端调用，使用服务器配置的 `OPENAI_BASE_URL`、`OPENAI_API_KEY` 和 `OPENAI_MODEL`。没有配置真实 ASR/LLM 时，系统显示未配置或失败状态，不返回假分析。

## 验收标准

1. 已安排面试可以创建会话并明确展示麦克风授权和录音状态。
2. 一次启动后可自动生成带时间戳的转写片段和匿名说话人 ID。
3. 角色映射同时使用面试阶段、文本语义和说话人连续性，并可人工修正。
4. 真实 LLM 配置可对候选人回答生成结构化分析和下一题；未配置时可恢复、无伪成功。
5. 会话历史可重新打开，看到音频/转写/问题/分析/修正记录和审计事件。
6. 不影响原有人工反馈、锁定反馈和完成面试流程。
