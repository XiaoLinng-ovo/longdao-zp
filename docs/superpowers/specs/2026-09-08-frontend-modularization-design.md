# 内部招聘平台前端模块化设计

## 1. 目标与边界

本阶段将现有 `index.html` 中混合的页面、样式、路由和展示逻辑拆分为独立的 Vue 3 + TypeScript + Vite 前端工程。目标是建立可维护的业务模块边界与路由结构，保留现有演示页面作为行为与内容参考，不迁移或改造正式后端、认证、权限决策、AI 服务和数据库。

新前端首批使用本地只读演示数据适配层，页面不得再读写旧页面的全局 `state`，也不得在浏览器中保存或调用模型密钥。

## 2. 交付范围

### 包含

- 在仓库根目录新建 `web/`，作为唯一的新前端工程。
- 建立应用启动、路由、主布局、侧边栏、顶栏和全局通知。
- 建立仪表盘、招聘需求、岗位、候选人、面试、Offer、报表和管理后台的路由入口与页面模块。
- 提取状态标签、页面标题、空状态、加载状态和基础表格等无业务规则的共享组件。
- 将首批页面从演示数据适配层读取数据，保证可通过 URL 直接访问和刷新。
- 保留旧 `index.html` 与现有 Node/Cloudflare 兼容入口，直到相应业务 API 和数据迁移完成。

### 不包含

- 修改现有 `server.mjs`、Cloudflare Functions、AI 分析服务或数据存储实现。
- 在前端实现最终的认证、授权或流程状态转移判断。
- 将浏览器会话模型密钥配置迁移到新前端。
- 删除旧单页或将其全量业务逻辑机械搬运到 Vue。

## 3. 工程与目录

```text
web/
  index.html
  package.json
  tsconfig.json
  vite.config.ts
  src/
    main.ts
    App.vue
    app/
      router.ts
      routes.ts
      layout/
      navigation.ts
    modules/
      dashboard/
      requisitions/
      jobs/
      candidates/
      interviews/
      offers/
      reports/
      administration/
    shared/
      api/
      components/
      data/
      types/
      styles/
```

每个业务模块统一采用以下目录契约：

```text
modules/<domain>/
  pages/          路由页面，组合组件并处理页面级交互
  components/     只服务于该业务域的展示组件
  api/            该业务域未来的 HTTP 调用与 DTO 映射
  types/          该业务域的前端类型
```

`shared/components` 只放无招聘流程含义的界面组件。业务模块页面不得向其他模块的内部组件或演示数据文件直接读取数据；跨模块引用通过 `shared` 类型或明确的模块公开入口完成。

## 4. 路由与页面

| 路由 | 页面 | 首批职责 |
| --- | --- | --- |
| `/` | DashboardPage | 展示招聘概览、待处理事项和招聘漏斗摘要。 |
| `/requisitions` | RequisitionListPage | 展示招聘需求列表、审批状态与编制摘要。 |
| `/jobs` | JobListPage | 展示岗位、JD、发布状态和渠道摘要。 |
| `/candidates` | CandidateListPage | 展示候选人列表、简历与 AI 分析状态摘要。 |
| `/interviews` | InterviewListPage | 展示面试轮次、时间、面试官和反馈状态。 |
| `/offers` | OfferListPage | 展示 Offer 审批、发放和接受状态。 |
| `/reports` | ReportOverviewPage | 展示漏斗、渠道和周期统计摘要。 |
| `/administration` | AdministrationPage | 展示管理员配置入口和安全配置提示，不显示或录入任何密钥。 |

未知路由重定向至 `/`。每个路由定义标题与导航标签；刷新或使用浏览器前进后退必须保留当前路由。第一批不实现旧单页中基于 query string 打开的详情弹窗，详情页和编辑页在后续业务 API 迁移时以嵌套路由或受控对话框实现。

## 5. 数据与状态边界

`shared/data/demo-recruiting-data.ts` 是首批唯一的演示数据入口。它导出按业务域组织的只读 DTO，不暴露旧页面的可变 `state` 结构。页面通过模块 API 适配层读取 DTO；首批 API 为同步只读函数，未来替换为 HTTP 调用时保持页面调用契约不变。

页面本地状态仅用于筛选条件、当前视图和临时 UI 状态。候选人、职位申请、面试和 Offer 的正式状态转换不在这一阶段提供写操作。若用户触发暂未迁移的操作，界面显示不可用状态或说明，不伪造成功写入。

## 6. 视觉与交互

新界面沿用现有招聘后台的深色侧栏、浅色工作区、紧凑表格与状态色语义，但重建样式为可组合的 CSS。布局使用固定宽度侧栏、响应式主内容区和可滚动表格；小屏幕下侧栏收起为顶部导航菜单。

按钮只承载已实现的命令。首批列表页提供可扫描的状态、数量和最后更新时间，不提供会修改演示数据的伪操作。加载、空数据、错误与无权限界面使用统一共享组件。

## 7. 迁移顺序

1. 建立 Vite、TypeScript、Vue Router、应用壳和全局样式。
2. 建立共享类型、演示数据适配层和共享展示组件。
3. 并行实现仪表盘、招聘需求、岗位、候选人四个首批核心模块。
4. 并行实现面试、Offer、报表和管理后台模块。
5. 集成导航、路由标题、响应式布局和跨页面视觉检查。
6. 为路由、数据适配层和关键共享组件添加测试；新前端构建通过后，才将其接入部署配置。

## 8. 错误处理与质量

- 演示数据适配层将来替换为 HTTP 时，统一错误映射为 `ErrorState`，不得在各页面散落 `fetch` 调用。
- 所有路由使用懒加载，避免首次加载所有业务页面。
- TypeScript 启用严格模式；页面和组件不得使用隐式 `any`。
- 新工程必须提供 `dev`、`build`、`typecheck` 和测试命令。
- 不修改旧单页的交互行为；新工程通过独立端口开发和验证。

## 9. 验收标准

- `web/` 能独立安装依赖、启动开发服务器并完成生产构建。
- 8 个业务路由都可直接访问、刷新和通过侧边栏切换。
- 所有路由从模块 API 适配层获取只读演示数据，不引用旧页面的全局状态。
- 共享组件不含招聘流程判断；招聘页面不直接调用 `fetch`。
- 新前端不包含模型 API Key 输入、持久化或直接模型调用代码。
- 桌面和窄屏视口下导航、表格和文本不发生重叠或溢出。
- 旧 `index.html`、`server.mjs` 和 Cloudflare 兼容入口保持可用且未被本阶段改动。
