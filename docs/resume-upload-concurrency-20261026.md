## 已生效的行为

- 页面同时上传 **3 份**简历，剩余文件在本地等待；上传和解析相互独立，上传后立即进入后台解析队列。
- Worker 默认及本机 `.env` 均为 `WORKER_CONCURRENCY=3`，同时解析 **3 份**，其余任务留在 PostgreSQL 中等待。不是把整个批次串行解析，也不是无限制并发。
- 单批次最多 **500 份**，单文件最多 **10 MiB**；同批次关联一个岗位，每份简历独立建档、解析和评分。
- API 默认限制单进程最多 **6 路上传**、单工作空间最多 **3 路上传**。多个页面和用户不能绕开该工作空间上限。
- 全局待解析/解析中任务达到 **2000**，或当前工作空间达到 **500** 时，停止接收新的文件内容，返回可重试的 429，不创建候选人或解析任务。
- 上传通道繁忙返回 `RESUME_UPLOAD_BUSY`、`Retry-After: 2`；解析队列满返回 `RESUME_ANALYSIS_QUEUE_FULL`、`Retry-After: 10`。读取接口不占上传通道。
- 前端对拥堵、网络中断、上传超时和临时网关错误进行退避加随机抖动的重试，最多自动重试 **5 次**，等待可取消；用尽后保留文件和批次供手动重试。
- 同一个批次上传项的并发提交受租户级 PostgreSQL advisory lock 保护，已提交项重试复用原任务。不同文件仍能并行。
- 刷新后重新选择同名、同大小、同 MIME 的待上传文件，会绑定回原服务端上传项，保留批次和文件标识。中断超过 2 分钟的上传可重新选择并重试。
- 已完成上传但后台解析失败的文件不会被重新上传；关闭弹窗不取消工作，取消剩余上传也不撤销已提交的解析任务。

## 修复内容

1. 上传服务新增数据库会话级防重锁和取消状态领取条件。候选人、岗位申请及上传结果保留检查点；批次汇总写入失败不再把已经提交的文件标记为上传失败。
2. API 新增上传准入中间件，在读取大型 base64 请求体前限制并发、检查解析积压，并在错误或完成后归还通道。HTTP 服务关闭时释放新增的队列检查连接池。
3. Worker 默认并发、环境示例和一键启动脚本统一调整为 3。既有数据库领取、租约、attempt fencing 和失败分类继续保留。
4. 页面修复刷新续传、同名文件绑定、缺失上传标识的错误展示、不匹配文件的明确拒绝、失败批次跟踪，以及解析失败和上传失败的区分。
5. 上传 XHR 保留状态码、错误码及服务端等待提示；重试使用原上传项，永久校验错误和取消不会自动重试。

## 适用边界

- 上传通道上限是**单 API 进程**的限制；积压水位来自共享数据库，但不是跨实例原子预留，水位附近可有少量并发超调。多实例部署若需要严格全局上限，应另做共享准入。
- 上传防重锁依赖固定 PostgreSQL 会话，本机直连部署适用；不能直接把连接改为 transaction-mode PgBouncer 而仍依赖该会话锁。
- 防重回归覆盖正常并发、请求重试和取消。候选人/申请/文件创建与上传项检查点不在同一个数据库事务中，数据库连接在副作用成功但检查点写入前丢失，仍属于需要额外事务或幂等设计覆盖的灾难窗口；没有承诺任意故障下严格 exactly-once。
- 前端刷新不能恢复浏览器 File 对象，必须重新选择对应本地文件；这不是字节级断点续传。无匹配的新文件需新批次。
- 没有执行真实 PDF/DOCX/OCR、付费 AI、MinIO、公网长时压测或恶意文件安全测试。历史失败任务不会被自动重新提交，避免重复费用或错误跨企业调用。
