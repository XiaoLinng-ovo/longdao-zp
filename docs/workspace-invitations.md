# 企业邀请码与成员管理

## 管理员生成、复制和发送邀请

1. 进入「企业工作空间」，在自己管理的企业旁点击「成员与邀请」。
2. 选择企业身份、业务角色、部门与有效期（1 / 3 / 7 / 30 天）。部门负责人必须选择部门。
3. 建议填写接收邮箱，填写后只有该邮箱登录的账号能使用邀请。
4. 点击「生成邀请」，复制邀请码或邀请链接，发给同事。
5. 「分享 / 发送邀请」优先打开系统分享面板；不支持时复制完整邀请文本，可粘贴到钉钉、微信或邮件。
6. 「邮件邀请（本机）」仅打开本机邮件编辑器，管理员需要自行确认发送。平台尚未接入 SMTP 或邮件供应商，不会自动投递邮件。

注意：当前若访问 127.0.0.1 / localhost，复制出的链接只能在本机打开。给其他电脑发送邀请时，需先部署或使用平台可访问的局域网 / 公网地址，并从该地址复制邀请链接；也可让同事在可访问的平台中输入邀请码。

## 接收人加入企业

- 已有账号：使用自己的邮箱和密码登录；邀请码不是登录密码。
- 没有账号：先注册，登录后使用邀请码加入。
- 打开邀请链接会保留邀请码，并在登录 / 注册后返回加入页面。
- 也可从登录页「已有邀请码？加入企业」进入，在企业工作空间中输入 / 粘贴邀请码或完整邀请链接。
- 点击「验证邀请码」，检查企业、企业身份和业务角色，再点击「确认加入企业」。
- 加入成功后自动切换企业。如果切换失败，可从企业列表手动进入，无需再次消费邀请。

## 权限与安全边界

- 企业身份：所有者 / 企业管理员 / 普通成员，用于企业与邀请管理。
- 业务角色：招聘专员 / 部门负责人 / 审批人 / 面试官，沿用平台现有业务权限规则。
- 仅企业所有者可以邀请企业管理员或修改管理员身份。
- 普通成员不能生成、查看或撤销邀请。不能修改自己或企业所有者。
- 邀请不能授予平台系统管理员或 HR 管理员。
- 邀请授予的业务角色按企业保存，切换企业不会把这一角色写入全局用户角色。
- 每个邀请码仅可消费一次，过期、已使用、撤销或企业已归档时拒绝加入。
- 已是企业成员时不消费邀请码；邀请码绑定邮箱不匹配时拒绝加入。
- 生成、撤销、加入和成员权限更新有审计记录。
- 不限邮箱的邀请码可由任何获得它的人消费，仅应发给可信同事，不要公开发布。
- 此模块不新增职位级 ACL；具体职位访问范围仍按现有业务权限实现，不承诺新增加逐职位授权。

## 启用

按顺序构建 API、迁移数据库，然后重启 API 并启动前端：

~~~powershell
npm --prefix apps/api run build
node scripts/migrate-postgres.mjs
pnpm --dir apps/api start
pnpm --dir web dev --host 127.0.0.1 --port 5174
~~~

迁移为 0031_workspace_invitations.sql，无须重新运行种子脚本或重置已有账号。
