# 企业共享邀请与成员管理

## 邀请规则

- 管理员生成邀请时不填写邮箱，不选择成员身份、部门或有效期。
- 一个邀请码可供多人使用，从生成时间起固定有效 72 小时。
- 企业已有有效邀请时，生成操作返回原邀请，不延长有效期。
- 重新生成需要确认，旧邀请立即撤销。撤销不影响已经加入的成员。
- 新成员一律以普通成员、企业用户身份加入，无预设部门。
- 邀请不会获得平台运营权限，也不会覆盖已有成员的身份或恢复停用成员。
- 不要把邀请发布在公开渠道，持有有效邀请且尚未绑定其他企业的已注册用户可以加入。

## 加入流程

1. 打开邀请链接后，先看到目标企业和有效期。
2. 没有账号：选择“注册并加入”，仅填写个人信息并验证自己的邮箱；不填写企业名称、不创建新企业。账号创建、验证码消费和成员绑定在同一数据库事务中完成。
3. 已有账号：选择“登录并加入”，登录后回到邀请页确认加入。
4. 已登录：显示当前账号，可确认加入或选择其他账号。
5. 已是有效成员：直接进入，不重复加入，也不修改原有权限。
6. 已加入但自动进入失败：重试进入，或从企业信息页进入，不需要重复注册。
7. 普通注册先创建未绑定账号，再选择创建或加入企业；无效的受邀注册不会自动退回创建企业。
8. 已绑定其他企业：拒绝加入，需原企业管理员办理正式退出；停用、归档和服务到期都不会释放绑定。

单企业约束、退出交接及存量迁移流程见 [单账号单企业](single-enterprise-membership.md)。

邀请链接使用 /join?invite=...，兼容旧 /workspaces?invite=... 链接。邀请码只能用于加入企业，不能代替登录密码。

## 加入后的管理

- 主管理员可以任免子管理员、修改成员部门、停用或恢复成员。
- 子管理员只能管理普通成员，不能提升自己或管理其他管理员。
- 主管理员可交接给本企业已启用的成员；需填写交接原因并验证当前账号密码。
- 交接在事务中完成，始终保留唯一主管理员，原主管理员降为子管理员。
- 成员设置不修改全局账号角色；审计写入目标企业，并保留迁移切换前的审计镜像机制。

## 升级与验证

本次新增迁移 0109_shared_workspace_invitations.sql，依赖此前迁移全部完成。
迁移将撤销尚未接受的旧版单人邀请，避免旧邀请码被静默升级为共享邀请；历史邀请及已有成员保留。
正式升级需按仓库维护审批流程检查迁移计划、完成备份及恢复验证，协调数据库、API 和前端版本后再启用。不要只发布前端或把旧 API 与新共享邀请混用。

测试命令：

~~~powershell
npm --prefix apps/api run build:production
npm --prefix web run typecheck
npm --prefix web test -- src/modules/auth src/app/router.test.ts
node scripts/test-shared-workspace-invitations.mjs D:/software/pgsql/bin
~~~

数据库集成测试脚本必须显式指定 PostgreSQL 工具目录，新建专用临时数据库簇和随机测试库、应用迁移，验证多人并发加入、受邀注册回滚和权限交接，最后删除测试库并停止专用簇。禁止回退到业务数据库，不使用正式账号或业务数据。

分享时请从同事可访问的公网或局域网地址打开平台，再复制链接。localhost / 127.0.0.1 链接仅在本机有效。
