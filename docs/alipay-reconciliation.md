# 支付宝手机网站支付、环境隔离与官方账单对账

本轮代码支持手机网站支付、沙箱渠道以及官方业务账单自动核对。迁移 0086 只在 15433 隔离测试数据库验收，业务环境尚未应用、重启或启用本轮功能；未使用真实商户发起支付或退款。

## 沙箱与正式环境

沙箱是支付宝提供的独立联调环境，使用沙箱应用、密钥及买卖家账号，不产生正式资金交易。系统管理员创建支付宝渠道时选择“正式收款”或“沙箱测试”，未填写 environment 的旧配置默认为 production。网关由服务端按环境固定选择，用户不能输入任意网关地址。

渠道配置不可原地修改。切换到正式收款时，新建正式渠道、填写正式 AppID、sellerId、应用私钥和支付宝公钥，再停用测试渠道。每个订单固定关联原渠道及环境快照；停用原渠道不会阻止历史订单查单、通知验签或退款。不要删除旧配置或丢失 PAYMENT_ENCRYPTION_KEY。

沙箱订单及渠道在页面明确标记。沙箱付款成功记录为 review，原因是“支付宝沙箱测试付款，不发放正式套餐权益”，不会开通正式企业套餐或发放企业额度。沙箱不参与正式账单对账。

## 手机网站支付

企业付款页新增“手机网站支付”，只在支付宝官方渠道下可用。服务端使用 alipay.trade.wap.pay，product_code=QUICK_WAP_WAY，采用 RSA2 签名，并设置固定 notify_url、return_url 和 quit_url。切换到不支持此模式的渠道时，界面恢复二维码选项，接口也会拒绝不支持的组合。

订单创建后，成员从付款页按钮跳转支付宝收银台。回跳页面只展示状态，到账以验签通过的通知或服务端查单为准；不能根据浏览器参数发放权益。新支付宝订单保存官方支付时间（gmt_payment / send_pay_date），减少跨日通知导致的账单日期差异。

所有有效企业成员均可发起购买、续费和继续支付企业已有订单，仍执行同一企业仅一个有效待支付订单的规则。套餐、席位、岗位和有效期属于企业。商户配置、商品管理、退款及对账仅允许系统管理员。

正式启用前，商户必须在开放平台开通相应手机网站支付产品及接口能力，配置正确公钥、有效公网 HTTPS 回调和结果地址，并在真实手机浏览器完成收银台、返回、取消、重复通知、断网恢复及小额收退款验收。

## 官方业务账单与调度

调用 alipay.data.dataservice.bill.downloadurl.query，bill_type=trade，bill_date 使用北京时间 yyyy-MM-dd。先验证支付宝响应签名，再立即下载临时账单地址。下载地址有有效期，系统不持久化临时 URL，也不向普通企业成员返回该地址。此处核对的是交易收款与退款业务账单，不是支付宝余额、手续费或银行结算资金账单。

后台复用每分钟的支付补偿轮询：北京时间每天 10:00 后核对前一天并补查最近 7 天，每轮最多处理 2 张账单。账单未生成、接口错误或下载解析失败后，至少间隔 1 小时重试；一致或存在差异的报告自动跳过。多实例通过数据库 advisory lock 互斥，同一渠道同一天不会并发重复执行。只有 API 进程及支付轮询运行时才会自动执行，停机期间由最近 7 天补查覆盖。较久的日期需管理员手动发起，手动日期限制为过去 366 天内已结束的日期。

支付宝对无交易日可能返回 BILL_NOT_EXIST。系统显示“账单未生成或无交易，待重试”，不会当作已核对一致。设置 PAYMENT_BILL_AUTO_ENABLED=false 可关闭账单自动下载，不影响原有签名查单及退款补偿。

账单按收款方 sellerId 和环境聚合同一商户的历史配置及应用下的本地订单，不能只比较当前渠道新订单。不同商户和沙箱账本不会混入正式本地账本。账单上其他系统产生的商户订单会标记为“账单有记录，本地无订单”，由管理员判断归属。历史配置无法解密时本次核对失败，避免漏掉可能属于同商户的历史订单。

## 比较、报告及差异处置

按商户订单号关联，并比较支付宝交易号、整数分金额、支付状态；退款额外精确匹配退款请求号。本地当日收款/退款也反向检查账单记录，报告包含：账单有而本地无、金额不符、交易号不符、本地未确认收款或退款、本地收款或退款未见账单记录。

报告保存日期、渠道、状态、尝试次数、ZIP SHA-256、总条目数、差异总数和最多 500 条必要差异字段，不保存买家账号等无关信息。差异计数超过 500 时页面明确提示截断。管理员可在“支付与商品管理”底部选择正式渠道、日期并填写原因，下载并重新核对；审计记录操作人和原因。接口为 GET /api/v1/platform/payments/bills 和 POST 同路径，写操作要求有效会话、可信 Origin、CSRF 及系统管理员权限。

差异报告不会自动改订单、开套餐或发起退款。先使用订单“核对”取得验签后的渠道证据，必要时由系统管理员处理退款，再重新下载对账；原有签名查单补偿继续独立运行。支付宝退款接口 code=10000 并不单独证明退款成功：本次资金变化 fund_change=Y 且订单/金额匹配才确认，否则保持 refund_pending，并使用原退款请求号查询结果。

已有历史订单的 paid_at 和退款 refunded_at 可能记录本地确认时间，临近午夜延迟确认时可能出现跨日差异；本轮新增支付宝收款使用官方支付时间，退款日期差异仍需结合官方退款查询与相邻日账单复核。

## 下载与解析边界

下载仅允许官方 dwbillcenter.alipay.com/downloadBillFile.resource，旧文档给出的 HTTP 链接升级为同主机 HTTPS；拒绝认证信息、私网 DNS、非标准端口及重定向。若官方新增域名或路径，需要核实并更新允许范围，不能自动放开任意地址。

受限读取 ZIP 中的业务明细 CSV，支持 UTF-8 / GB18030 编码、CSV 引号及跨行；校验 ZIP 目录、本地文件头、大小、压缩方式及 CRC。限制下载 20 MiB、总解压 40 MiB、最多 32 个文件、10 万条 CSV 行及单字段 64 KiB，超限或未知结构时任务失败，不能生成“一致”报告。

解析要求业务明细列包含“支付宝交易号、商户订单号、业务类型、订单金额（元）、退款批次号/请求号”，接受金额标题的半角括号。只接受交易/退款业务类型，退款缺少请求号、重复记录或非法金额直接失败。测试覆盖合成 UTF-8 与 GBK 账单；商户实际下载账单格式仍需在正式联调确认，不应把本地样例测试当成商户联调完成。

## 发布

1. 构建并备份数据库，使用 npm run db:status 查看全部待迁移项。
2. 按 docs/database-upgrades.md 的统一发布流程应用迁移；新增 0086_alipay_bills_wap.sql 增加渠道/订单环境、wap 模式和 payment_bill_runs 报告表。普通重启不会自动迁移。
3. 系统管理员创建并启用正确环境的支付宝渠道，发布商品；确认主密钥备份及固定公网 HTTPS 地址。
4. 沙箱完成支付链路后，新建正式渠道，按商户签约产品做真实小额验收；账单生成后确认业务明细格式、实际交易和退款对账结果。
