# 单账号单企业

一个账号最多保留一条未结束的企业成员关系。停用、企业归档、服务到期都不释放归属。
普通注册不填写企业名称，完成后进入创建/加入页。旧客户端显式提供企业名称时仍可在注册事务中创建唯一企业。
邀请注册直接加入企业；共享邀请码仍固定 72 小时、不限制邮箱、默认普通成员。

## 上线前检查

1. 使用目标环境配置运行只读检查：`node scripts/audit-single-enterprise.mjs`。报告包含个人信息，应按管理员资料保管。
2. 若存在多企业账号，暂停旧版本的创建与加入入口，逐个确认保留企业；主管理员先交接，其他关系明确办理退出并记录审计。不得按最近登录时间自动选取。
3. 完成数据库备份，在维护窗口执行正常迁移。0113 安装退出历史结构；0114 检测到冲突会拒绝创建唯一索引，不删除或自动选择存量绑定。若冲突阻止 0114，保持维护状态，按下述清单工具办理后重试迁移。
4. 数据库迁移、API、前端应作为同一次维护发布。校验唯一索引、退出流程、席位、旧会话和企业隔离后恢复访问。

## 存量冲突处理清单

清单 JSON 是一个数组，每项必须包含 organizationId（退出企业）、userId、actorId（该企业办理管理员）、replacementId（接收人）、keepOrganizationId（明确保留的企业）、reason。
先交接所有待退出的主管理员身份，再制定清单。清单的每一项走正式退出事务并留审计，不删除成员记录。

先运行只读预演：`node scripts/resolve-single-enterprise.mjs --plan <绝对清单路径>`。
确认备份、维护窗口和目标库后，增加 `--apply --expect-target <host:port/database> --maintenance-confirmed --backup-confirmed` 执行。没有这些参数不会写入。
每项独立事务，成功项保留；失败后查看审计、修正清单并重跑，已结束成员会跳过。保持旧版写入口关闭，完成后再次运行只读检查并重试 0114。

## 退出与历史

普通成员可以申请退出；主管理员不能申请退出，先交接或联系平台处理企业关闭。
管理员可驳回申请或指定接收人办理退出，也可以直接移除普通成员。子管理员不能移除其他管理员。
停用可立即撤销访问，无需先完成工作交接。正式退出保存成员历史、原因和办理人，清理旧待办、撤销所有会话；再次加入默认普通成员，不恢复旧权限。
待办交接保留原企业数据，不转移候选人、录音、评分、Skill、余额或订阅到新企业。
服务到期或归档时，账号仍能查看归属与申请退出；管理员可以办理退出，不能借归档再创建第二家企业。
平台人工解除必须核验身份与企业归属，沿用退出审计流程，不能直接删除历史表。企业关闭及争议申请暂沿用人工支持渠道，不自动解除主管理员。

## 回滚

上线前验证备份可恢复；迁移失败回滚事务，处理冲突后重试。代码回滚不能移除唯一绑定约束，不能恢复已正式结束的企业权限。
已办理的退出与交接只能通过新的、有审计的业务操作纠正。不要自动恢复旧会话。
