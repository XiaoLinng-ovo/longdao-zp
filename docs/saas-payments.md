# 企业套餐与正式支付

本次新增正式支付账本，独立于 0037 模拟账本。支持微信 API v3 Native / H5、支付宝 RSA2 预创建 / 电脑页面跳转 / 手机网站支付、EasyPay 兼容协议二维码 / 页面跳转。真实商户尚需配置并完成渠道联调；本地验收不会产生真实收款。

现行管理员边界、续费判定、历史退款恢复与安全上线说明见 [四阶段实施与验收](reliability-implementation-20261112.md)。

## 页面与权限

- 企业管理 → 套餐订购与续费：`/enterprise/payments`。所有有效企业成员均可购买、续费、查看本企业订单、查单和取消，不再要求 owner/admin 身份。有效成员指账号启用、成员关系仍存在且企业未归档。
- 独立付款页：`/enterprise/payments/:id?workspace=<企业ID>`，展示二维码或安全的 HTTPS 跳转按钮、到期倒计时和订单结果。
- 系统管理 → 支付与商品管理：`/platform/payments`。仅系统管理员可查看支付后台、发布商品、上下架、配置支付宝等渠道、异常核对及全额退款。通过 `SYSTEM_ADMIN_USER_NO` 绑定启用账号；旧 platform admin/viewer 授权不再赋予支付后台权限。
- 到期企业的任何有效成员可从工作空间的「购买 / 续费套餐」进入账单页面。该通道检查实时企业成员身份，不恢复招聘业务权限；暂停和归档企业不允许新购买。
- 模拟入口及账本继续独立保留，模拟成功不能改变正式套餐。

## 定价与履约规则

1. 平台先发布套餐容量版本，再创建商品售价版本；售价按整数分存储，支持 1～1 亿分。期限可选择 1～3660 天或 1～120 个自然月，二选一。正式商品独立发布，不使用模拟套餐兜底。
2. 新商品默认下架，管理员确认后上架；「编辑并上架」在同一商品下发布新版本并停止旧版销售，主列表只展示当前版本。「复制为新商品」才创建独立商品。已有订单保存原始金额、容量版本和期限快照，详见 [商品版本管理](payment-product-versions.md)。
3. 下单不接受客户端金额、企业 ID 或任意回跳地址。企业来自账单路由并经实时成员权限验证；订单价格来自数据库。原支付实例与密钥版本绑定订单。
4. 同套餐续费从当前未过期期限顺延；切换套餐从付款确认时间开始。原按天商品保持固定天数；按月商品按上海时区的自然月计算，月末自动取目标月最后一天。均为单次付款，不自动扣款。目标套餐不能低于当前席位、岗位用量。
5. 到账、通知事件、企业套餐和审计记录在同一数据库事务提交。订单/企业行锁、交易号唯一约束和创建幂等键防止并发重复发放。
6. 取消/过期、企业被暂停、权益版本变化或容量不足后的付款进入待人工核对，不自动覆盖企业权益；管理员可以核对后全额退款。
7. 创建请求超时保存 `uncertain`，查单恢复，重复同键不会再次调用上游创建。付款页面中的浏览器参数不会被当作到账证明。
8. 套餐、席位、岗位数量和有效期均属于企业。付款用户仅记录为订单操作人；支付成功后全体有效成员共享企业权益。成员退出不改变企业套餐，但立即失去该企业订单及其他资源的访问权。
9. 同一企业同一时间只允许一个未过期且状态为 `creating`、`pending` 或 `uncertain` 的订单；其中有取消申请但渠道尚未确认的订单，即使已过期也继续占用名额，防止重复付款。创建订单在企业行锁内检查并分配，跨成员、不同幂等键的并发请求也只能创建一次；冲突返回 HTTP 409 `PAYMENT_ORDER_ALREADY_PENDING` 和已有订单 ID。
10. 订购页单独返回 `pendingOrder`，不受最近 50 笔历史记录限制。其他成员可以继续支付或取消已有订单；已取消、已过期、已退款订单不占用待支付名额。超时未确认订单在有效期内仍占用名额，防止重复付款。页面每 15 秒刷新企业共享订单；其他成员取消或完成付款后同步状态，不清空当前套餐选择。未申请取消的待支付订单有效期结束后释放页面购买入口，最终创建仍由服务端校验；取消待确认的订单需等渠道确认后释放。
11. 席位上限阻止新增成员，不移除或禁用现有成员。套餐到期后保留登录、账单、续费，以及下述受限只读、导出和联系系统管理员入口；创建岗位、上传简历、发起面试等招聘写操作仍由企业权益校验统一阻止。

## 取消订单与渠道异常

- 先持久化取消申请与操作审计，再向原订单绑定的支付渠道查单、关单。重复申请不会重复写入申请审计；已付款订单不能取消，也不会因关单与到账回调并发而覆盖为已取消。
- 网络阻断、DNS 故障、支付宝应用未上线或渠道未确认结果时，保留原财务状态，界面显示「取消待确认」及中文原因，隐藏二维码和付款链接。后台持续重试，包括已过期或创建超过七天的未确认取消申请。
- 只有渠道确认关单，或经响应验签确认支付宝交易不存在，才能完成取消。应用未上线不等于交易不存在；不可直接清除订单或假定取消成功。
- 上线前应用 `0088_payment_cancellation_requests.sql`，为现有订单增加可空的取消申请时间、渠道错误码及重试索引，不改写现有订单的付款或取消状态。随后重新启动已构建的 API；只构建前端不能让后端逻辑生效。
- 回归验证：`payment-cancellation.postgres.integration.test.ts` 使用事务内隔离结构和虚构渠道、全部回滚；`node scripts/verify-payment-cancellation.mjs` 使用隔离页面与模拟接口检查桌面和手机取消流程，不读取商户密钥、不访问真实支付服务。以上不代表真实商户关单已完成。

## 到期后的企业数据与服务支持

- 工作空间中到期企业显示「只读数据 / 联系管理员」，进入企业付款页的「企业数据与服务支持」面板。已选择其他企业时，也可查看自己所属企业的账单、续费和服务面板，不需要恢复该企业的招聘权限。
- 所有数据接口实时校验启用账号、成员关系及未归档企业。界面只读范围为：岗位、应聘记录和面试数量统计，以及最近 100 条岗位摘要（编号、名称、状态、招聘人数、创建与更新时间）。不开放候选人个人资料、简历文件、面试录音及招聘写操作。
- 受限导出为最近最多 1000 条岗位摘要 CSV；超过上限会明确提示，导出记录写入平台审计。CSV 单元格处理公式注入字符。启用企业 Schema 路由时只读取已注册且 ready 的对应企业 Schema，未就绪时不退回 public 数据。
- 企业服务被管理员暂停时，仅保留账单与联系入口，不开放招聘数据和导出。数据 Schema 未就绪不会阻断工单提交。
- 联系管理员采用站内企业服务工单：有效成员均可提交和查看本企业最近 20 条工单，在同一工单中连续追问、补充附件并查看完整会话。系统管理员在支付后台查看最近 100 条工单（待处理优先），可“仅回复，保持待处理”或“回复并完成工单”。会话按时间分页，每页 50 条，可加载更早消息。
- 同一企业只保留一个待处理工单，并发新建返回已有工单。页面保留本次未提交的草稿和附件，提示到已有会话继续沟通。已完成工单可通过追问重新打开；若企业已另开一张待处理工单，则拒绝重新打开旧单，要求在当前待处理工单沟通。企业行锁及数据库唯一约束共同保证并发一致性。
- 首次提问及后续成员/管理员消息均可附 PNG、JPG、PDF、UTF-8 TXT；每条最多 3 个，每个不超过 2 MiB，每张工单累计不超过 30 MiB。消息正文仍需 2–2000 字。前端先检查类型与大小；服务端校验文件名、规范 Base64、大小、扩展名与基本文件标识。这些检查不代表病毒扫描。
- 小体积附件使用 PostgreSQL bytea 私有存储，消息与附件在同一事务写入，超限整条回滚。列表和会话只返回附件元数据；下载通过登录态接口重新验证企业有效成员或系统管理员资格，并校验附件所属工单，使用 no-store 响应，以下载方式保存文件。退出企业或禁用账号后失去下载权限。消息、处理状态和下载操作均保留审计；不提供公开附件 URL。
- 该功能不依赖虚构的客服邮箱，不向管理员发送站外消息；企业成员通过本页面刷新查看处理回复。

## 历史重复待支付订单

系统管理员后台独立列出最多 100 家存在多个有效待支付订单的企业，列出组内全部有效待付订单，不受最新 100 笔订单限制。管理员可逐单查询并填写原因后关闭多余订单；渠道确认付款时先处理到账，未知结果或关闭失败时保留原状态。未自动批量关闭历史订单，不执行真实退款；`creating` 订单需先查询恢复为可处理状态或等待过期后核对。新订单创建仍按企业行锁保证只有一张有效待支付订单。

## 发布正式套餐目录

企业页面显示“暂无在售套餐”表示正式商品尚未发布或上架，与模拟账本无关。系统管理员可在“支付与商品管理”独立发布并上架正式商品。

构建 API 并应用 `0049_payment_calendar_products.sql` 后，也可显式发布标准目录：

```sh
node scripts/publish-payment-catalog.mjs --actor <系统管理员ID> --confirm-prices --activate
```

标准目录为全功能年付套餐（2500 元 / 12 个自然月）、半年套餐（1300 元 / 6 个自然月）、月付套餐（258 元 / 1 个自然月），均为 100 个席位、2000 个岗位。脚本要求明确确认价格；省略 `--activate` 仅创建下架草稿。重复执行保留已有同名商品的价格及上下架状态，不覆盖管理员设置。发布和上架保留审计记录，不启用收款渠道、不创建订单、不变更企业权益。

## 收款配置

服务端环境参数：

```dotenv
PAYMENT_ENCRYPTION_KEY=<32 字节随机密钥的 Base64>
PAYMENT_PUBLIC_BASE_URL=https://招聘平台公网根域名
PAYMENT_TRUSTED_PROXY_IPS=<可选，逗号分隔的可信反向代理 IP>
SYSTEM_ADMIN_USER_NO=<系统管理员账号编号，格式 USR-XXXXXXXXXX>
```

可以在构建 API 后运行 `node scripts/provision-payment-encryption-key.mjs`，脚本只生成一次，不输出、不覆盖已有主密钥。数据库保存带支付实例 AAD 的 AES-256-GCM 密文；私钥和商户密钥不会从后台 GET 接口返回。必须安全备份主密钥，不能直接换主密钥，否则历史订单无法解密配置。

公网地址只接受公开域名的 HTTPS 根 origin，回调和结果 URL 均由服务端生成。不从 Host、Referer 或客户请求拼接任意回跳 URL。EasyPay 接口要求公开 HTTPS 域名；出站请求验证并固定 DNS 地址、拒绝私有网络和 HTTP 跳转，限制响应大小和超时。

本机代理可能将支付宝域名解析为 `198.18.0.0/15` 的 Fake-IP。仅支付宝正式、沙箱官方网关的全部解析结果均为该地址段时，API 才会通过固定的阿里公共 DNS HTTPS 接口重新解析，并再次检查、固定真实公网地址。DNS 接口自身固定连接 `223.5.5.5`，保留主机名 TLS 验证，不接受重定向，并限制大小和超时。其他域名、私网地址、混合公网/私网结果仍拒绝访问，不会全局放开代理地址。

查单收到验签有效的 `40003 / isv.not-online-app` 时，会提示“支付宝应用尚未上线”，需在支付宝开放平台完成上线。预下单失败日志仅保存订单 ID 和平台内部错误码，不记录密钥、签名或原始渠道响应。数据库创建成功、查单连通和真实支付成功是不同验收阶段，不能相互替代。

渠道配置：

| 接口 | 参数 | 付款模式 |
| --- | --- | --- |
| 微信官方 | App ID、商户号、商户 RSA 私钥、证书序列号、API v3 Key、微信支付公钥及公钥 ID | Native 扫码；H5 跳转（手机浏览器） |
| 支付宝官方 | App ID、应用 RSA 私钥、支付宝公钥、收款 seller_id | 预创建扫码；网页支付跳转 |
| EasyPay | HTTPS 接口前缀、PID、pkey | mapi.php 二维码；submit.php 跳转 |

微信 Native 与 H5、支付宝当面付与电脑网页支付必须在对应商户平台开通。支付宝支持正式与沙箱环境快照；沙箱订单不发放正式套餐权益，不包含微信公众号 JSAPI/OAuth。正式收款前应使用已开通商户在 HTTPS 测试部署完成低金额验收。

新渠道默认停用，启用前检查密钥和公网地址。轮换凭据时新增配置实例并停用旧实例；旧实例继续支持旧订单回调、查单及退款。不提供修改/删除历史密钥的接口。可信代理必须追加或重写可信的 X-Forwarded-For，服务端从右侧可信链解析 H5 客户 IP；不信任任意客户端转发头。

## 回调、查单和退款

统一公共回调：`/api/v1/payments/webhook/:providerId`。支付宝和微信 POST，EasyPay 可 GET/POST；限制原始回调 64 KiB，拒绝重复表单参数。

- 微信：RSA-SHA256 验证原文、时间戳五分钟窗口、公钥 ID，再 AES-GCM 解密，绑定 App ID / 商户号 / 币种 / 金额。主动接口响应也验签。
- 支付宝：RSA2 验签，强制匹配 App ID / seller_id，使用 total_amount 的严格整数分转换。网关响应使用原始 JSON 字节验签。
- EasyPay：协议 MD5 签名、固定参数白名单、PID 校验；成功回调还必须通过服务端认证查单确认金额和交易号。共享 MD5 协议及查询结果仍依赖渠道与 HTTPS 信任，不能等同于官方 RSA 协议。
- 不存在的订单、错误签名、错误金额返回失败，不把未验证通知 ACK 成功。合法完成微信回调返回 JSON SUCCESS，其他渠道返回纯文本 success。
- 客户查单和每分钟后台补偿使用数据库时间戳领取，避免多实例重复查询；失败保留未确认状态继续重试。每轮最多 20 单，覆盖近 7 天未完成、取消、过期及退款处理中的订单；超过 7 天须管理员手动查单。
- 退款限定系统管理员、全额退款和必填原因。企业成员包括付款操作人都无权退款或配置商户。先持久退款号再调用渠道；不确定结果保留 refund_pending，不自动新建第二次退款。微信/支付宝使用同一退款号主动查询。
- EasyPay 各平台退款协议存在差异：当前支持常见 api.php act=refund；不支持关闭订单及通用退款查单。无法确认的聚合退款保持待核对，须核对商户记录。正式使用前必须验证所选聚合平台的幂等与退款协议。
- 退款当前订单仅在企业权益版本仍对应本订单时回退。退款旧单不覆盖新单；不能恢复已退款的前序套餐。回退容量不足时暂停服务并审计，不删除成员或岗位。
