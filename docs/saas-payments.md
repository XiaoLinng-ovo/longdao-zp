# 企业套餐与正式支付

本次新增正式支付账本，独立于 0037 模拟账本。支持微信 API v3 Native / H5、支付宝 RSA2 预创建 / 页面跳转、EasyPay 兼容协议二维码 / 页面跳转。真实商户尚需配置并完成渠道联调；本地验收不会产生真实收款。

## 页面与权限

- 企业管理 → 套餐与支付：`/enterprise/payments`。企业所有者及管理员可购买、查看订单、查单和取消；普通成员无权访问。
- 独立付款页：`/enterprise/payments/:id?workspace=<企业ID>`，展示二维码或安全的 HTTPS 跳转按钮、到期倒计时和订单结果。
- 平台运营 → 支付与商品管理：`/platform/payments`。平台管理员可以发布售价、上下架、配置渠道、查询订单及全额退款；平台只读运营人员只能查看。
- 到期企业可从工作空间的「购买 / 续费套餐」进入账单页面。该通道只检查实时企业管理身份，不恢复招聘业务权限；暂停和归档企业不允许新购买。
- 模拟入口及账本继续独立保留，模拟成功不能改变正式套餐。

## 定价与履约规则

1. 平台先发布套餐容量版本，再创建商品售价版本；售价按整数分存储，支持 1～1 亿分、1～3660 天有效期。没有默认正式售价；模拟测试价不迁移。
2. 新商品默认下架，管理员确认后上架；调价必须发布新版本，下架旧商品。已有订单保存原始金额、容量版本和期限快照。
3. 下单不接受客户端金额、企业 ID 或任意回跳地址。企业来自账单路由并经实时成员权限验证；订单价格来自数据库。原支付实例与密钥版本绑定订单。
4. 同套餐续费从当前未过期期限顺延；切换套餐从付款确认时间开始。按固定天数计费，不是自动扣款或自然月订阅。目标套餐不能低于当前席位、岗位用量。
5. 到账、通知事件、企业套餐和审计记录在同一数据库事务提交。订单/企业行锁、交易号唯一约束和创建幂等键防止并发重复发放。
6. 取消/过期、企业被暂停、权益版本变化或容量不足后的付款进入待人工核对，不自动覆盖企业权益；管理员可以核对后全额退款。
7. 创建请求超时保存 `uncertain`，查单恢复，重复同键不会再次调用上游创建。付款页面中的浏览器参数不会被当作到账证明。

## 收款配置

服务端环境参数：

```dotenv
PAYMENT_ENCRYPTION_KEY=<32 字节随机密钥的 Base64>
PAYMENT_PUBLIC_BASE_URL=https://招聘平台公网根域名
PAYMENT_TRUSTED_PROXY_IPS=<可选，逗号分隔的可信反向代理 IP>
```

可以在构建 API 后运行 `node scripts/provision-payment-encryption-key.mjs`，脚本只生成一次，不输出、不覆盖已有主密钥。数据库保存带支付实例 AAD 的 AES-256-GCM 密文；私钥和商户密钥不会从后台 GET 接口返回。必须安全备份主密钥，不能直接换主密钥，否则历史订单无法解密配置。

公网地址只接受公开域名的 HTTPS 根 origin，回调和结果 URL 均由服务端生成。不从 Host、Referer 或客户请求拼接任意回跳 URL。EasyPay 接口要求公开 HTTPS 域名；出站请求验证并固定 DNS 地址、拒绝私有网络和 HTTP 跳转，限制响应大小和超时。

渠道配置：

| 接口 | 参数 | 付款模式 |
| --- | --- | --- |
| 微信官方 | App ID、商户号、商户 RSA 私钥、证书序列号、API v3 Key、微信支付公钥及公钥 ID | Native 扫码；H5 跳转（手机浏览器） |
| 支付宝官方 | App ID、应用 RSA 私钥、支付宝公钥、收款 seller_id | 预创建扫码；网页支付跳转 |
| EasyPay | HTTPS 接口前缀、PID、pkey | mapi.php 二维码；submit.php 跳转 |

微信 Native 与 H5、支付宝当面付与电脑网页支付必须在对应商户平台开通。这里使用生产网关，尚无支付宝沙箱开关，也不包含微信公众号 JSAPI/OAuth。正式收款前应使用已开通商户在 HTTPS 测试部署完成低金额验收。

新渠道默认停用，启用前检查密钥和公网地址。轮换凭据时新增配置实例并停用旧实例；旧实例继续支持旧订单回调、查单及退款。不提供修改/删除历史密钥的接口。可信代理必须追加或重写可信的 X-Forwarded-For，服务端从右侧可信链解析 H5 客户 IP；不信任任意客户端转发头。

## 回调、查单和退款

统一公共回调：`/api/v1/payments/webhook/:providerId`。支付宝和微信 POST，EasyPay 可 GET/POST；限制原始回调 64 KiB，拒绝重复表单参数。

- 微信：RSA-SHA256 验证原文、时间戳五分钟窗口、公钥 ID，再 AES-GCM 解密，绑定 App ID / 商户号 / 币种 / 金额。主动接口响应也验签。
- 支付宝：RSA2 验签，强制匹配 App ID / seller_id，使用 total_amount 的严格整数分转换。网关响应使用原始 JSON 字节验签。
- EasyPay：协议 MD5 签名、固定参数白名单、PID 校验；成功回调还必须通过服务端认证查单确认金额和交易号。共享 MD5 协议及查询结果仍依赖渠道与 HTTPS 信任，不能等同于官方 RSA 协议。
- 不存在的订单、错误签名、错误金额返回失败，不把未验证通知 ACK 成功。合法完成微信回调返回 JSON SUCCESS，其他渠道返回纯文本 success。
- 客户查单和每分钟后台补偿使用数据库时间戳领取，避免多实例重复查询；失败保留未确认状态继续重试。每轮最多 20 单，覆盖近 7 天未完成、取消、过期及退款处理中的订单；超过 7 天须管理员手动查单。
- 退款限定平台管理员、全额退款和必填原因。先持久退款号再调用渠道；不确定结果保留 refund_pending，不自动新建第二次退款。微信/支付宝使用同一退款号主动查询。
- EasyPay 各平台退款协议存在差异：当前支持常见 api.php act=refund；不支持关闭订单及通用退款查单。无法确认的聚合退款保持待核对，须核对商户记录。正式使用前必须验证所选聚合平台的幂等与退款协议。
- 退款当前订单仅在企业权益版本仍对应本订单时回退。退款旧单不覆盖新单；不能恢复已退款的前序套餐。回退容量不足时暂停服务并审计，不删除成员或岗位。

主要企业 API：

```text
GET  /api/v1/payments/workspaces/:org
POST /api/v1/payments/workspaces/:org/orders
GET  /api/v1/payments/workspaces/:org/orders/:id
POST /api/v1/payments/workspaces/:org/orders/:id/verify
POST /api/v1/payments/workspaces/:org/orders/:id/cancel
```

创建要求 Idempotency-Key；所有登录写接口都要求可信 Origin 与 CSRF。已选择企业时路由与 X-Workspace-Id 必须一致，到期企业允许明确的账单企业路径加实时成员校验。

主要平台 API：

```text
GET   /api/v1/platform/payments
POST  /api/v1/platform/payments/products
PATCH /api/v1/platform/payments/products/:id
POST  /api/v1/platform/payments/providers
PATCH /api/v1/platform/payments/providers/:id
POST  /api/v1/platform/payments/orders/:id/verify
POST  /api/v1/platform/payments/orders/:id/refund
```
