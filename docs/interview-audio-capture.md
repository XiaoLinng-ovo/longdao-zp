# 面试室音频采集使用与验证说明

## 2026-10-20 按音频来源独立转写（当前架构）

- 本机麦克风与会议共享音频不再先混音：各自保存原始文件、建立 FunASR 流式连接、维护全文检查点和上传队列。一路重连或上传失败不停止另一路；不调用 faster-whisper 后备转写。
- 两路使用同一个面试录音时钟，在开始录音和停止录音时确定时间边界，不采用数据回传时间或接口完成顺序。分段文字按开始/结束时间展示，允许双方插话、时间重叠。流式补偿缺少词级时间时，只承诺所属录音片段范围，不伪造精确说话边界。
- 采集设置新增每路的角色选择及“该路包含多人”。默认角色待确认、多人开启；本机麦克风不默认等于面试官。仅在用户明确选择角色并关闭多人时，才把该路整体映射到该角色。面试暂停后可修改，修改对后续录音生效，既有记录不自动重标。
- 每一路若有多人，继续使用该路内的声纹和现有角色确认；声纹身份不跨来源串用。分段失败后恢复的全文仍带来源，无法确认说话人时保持待确认，不凭语句猜测成候选人回答。
- 原音频弹窗标注来源，连续播放只接续同会话、同来源，不把另一条重叠音轨当作下一段。历史混音录音保留“来源未记录”，无法事后还原独立麦克风。
- 需要数据库迁移 0043_interview_audio_sources.sql，在分段表记录 audio_source，并在录音索引保存来源及当时的角色/多人设置。迁移只增加可空字段，不重写历史转写。
- 会议共享音频是一条浏览器输入，不等于每个远端参会者的独立麦克风；同一房间多人共用麦克风、远端多人混合、回声或串音仍需声纹及人工复核。推荐用耳机避免会议声音再次进入本机麦克风。
- 自动化验证使用模拟双源录音、逆序回传、重连、故障重试及 HTTP 保存/读取；真实双方插话和不同设备效果仍需双人短试录复核。
- 本轮前端相关 170 项测试、API 相关 58 项测试通过；PostgreSQL 集成测试另以事务回滚方式实际执行并通过。前端类型检查、前后端隔离目录构建通过。隔离浏览器在 1440×900 和 390×844 下验证来源设置、重叠时间及标签，无页面脚本错误或横向溢出；未采集真实声音、未写入模拟业务记录。
- 本地数据库已应用 0043，既有 2187 条转写及 604 条录音记录数量不变。本次仅在 dist/source-audio-check 生成验证构建，没有替换常规 API 构建或重启共享 API；当前运行服务需正常构建、重启后才会完整支持来源保存。部署完成前不应开始新的双路面试。

## 2026-10-20 流式重连修复

- “重新连接”立即重建流式 WebSocket 与音频推送节点，不重建面试会话、不停止独立录音，也不重新申请共享权限。连接中、模型加载中或断开时均可主动重试。
- WebSocket 握手限时 10 秒；握手成功后模型就绪限时 120 秒。就绪前不推送 PCM、不等待流式分段确认，录音仍按原流程分段保存和转写，避免模型加载期间反复确认超时重连。
- 连接错误、关闭、发送失败、发送积压、模型就绪超时、流式尾句确认超过 20 秒都会终止旧流式连接，按 1/2/4/8/15 秒封顶退避自动重试。暂停和结束时不启动重连；继续录音后可恢复重试。
- 新版 FunASR 就绪帧声明 heartbeat 支持，客户端每 10 秒发送 ping，服务回复 pong；连续约 35–40 秒无有效响应时重新连接。旧版服务不声明心跳时仍兼容连接，不把正常静音当作断线。
- 关闭旧连接会清理握手等待、计时器、事件监听与音频处理节点。旧连接的迟到消息或异步失败不能影响新连接。恢复成功只清除流式故障提示，不清除音量或采集设备提示。
- 中断前已识别的文字与独立录音继续保留；中断或就绪前覆盖不完整的分段仍交给分段转写，不标记为完整流式识别。断网期间上传仍依赖原有本地缓存与重试机制，不能保证语音识别服务持续可用。
- 自动化测试使用模拟音频采集和连接；真实服务测试只发送合成静音及控制帧，不采集现场声音、不改动候选人记录。仍需正式使用前短试录复核实际设备与网络环境。
- 本轮验证：面试录音页面、流式文本缓冲与音频采集共 125 项测试通过，语音服务 24 项测试通过；前端类型检查和生产构建通过。全量前端 685 项中 681 项通过，4 项失败位于本轮未改动的候选人申请排序模块。
- 重启本地 FunASR 后，直连与 Vite 代理各连续测试两次，均收到 ready（声明 heartbeat）、pong 和对应 commitId 的 final。首次冷加载约 16 秒，后续无需重复加载。浏览器已重新加载面试室，页面正常显示；未启动真实面试录音。

## 2026-10-19 转写分段修复

- 流式文本不再因一般识别差异而整段覆盖离线声纹分段；离线无文本或仅有未验证的极短残片时才采用完整流式兜底。
- 能明确对齐的遗漏前后文单独补齐；无法对齐的流式句子保留为待确认补充，时间仅表示所属录音分段范围，不伪造逐字时间。两路识别有分歧时可能保留相似文字，需核对原录音；待确认或重叠内容不能直接用作候选人评分依据。
- 声纹分段取消将不足 0.7 秒发言强行归给邻人的平滑；缺少声纹覆盖、重叠竞争或词时间不可靠的部分保持待确认，不再让一个模糊字影响整句的所有可信部分。
- 前端只合并同一说话人、角色已识别、置信度达标且时间不重叠的连续发言；待确认片段不再自动合成一大框。可信的五分钟连续回答仍可完整合并显示。
- 本轮不改变现有麦克风/会议混音采集架构，也未用真实双人通话测量浏览器录音切段间隙。自动化回归不能证明所有真实录音都不缺段或声纹角色百分之百正确，仍需双人实录复核。

## 两种采集方式

- **现场面试：仅麦克风**。只采集所选录音输入，适合线下面试或输入设备本身已提供混合音频的情况。不会自动获得桌面会议软件里的对方声音。
- **线上面试：麦克风 + 会议声音**。通过浏览器共享授权取得会议音轨，与所选麦克风分别录音和识别。不需要将平台账号绑定到钉钉或腾讯会议，也没有接入会议软件的官方接口。

采集设置位于 AI 面试室顶部。设置区采用紧凑卡片布局，不再常驻显示操作与注意事项长段落；仍保留录音同意、来源状态、音量条及必要的异常提示，详细操作说明见本文。在开始前可选择输入设备；“检查麦克风”会短暂申请权限用于显示设备名称，检测后立即关闭检测流，不会创建面试录音。

## 线上面试操作步骤

1. 向参与者说明录音、转写和 AI 辅助分析用途，取得同意，再勾选确认项。
2. 选择“线上面试：麦克风 + 会议声音”及合适的麦克风；按实际场景确认两路角色，只有确认该路仅有一人时才关闭“该路包含多人”。
3. 点击“开始面试”。浏览器会显示共享来源选择框，需要由用户自行选择来源并允许共享音频。
4. 桌面会议可尝试共享整个屏幕并勾选系统音频；网页会议可尝试选择对应标签页并勾选标签页音频。实际可选项和音轨支持取决于浏览器、操作系统及所选来源，不能保证仅共享应用窗口就有音频。
5. 让自己和对方分别说话，观察“麦克风输入音量”和“会议音频输入音量”。“音轨已接入”只表示获得了音轨，不保证音轨中有声音，必须核对音量条及试录转写结果。
6. 如果没有取得会议音轨，平台会明确报错并停止共享，不会静默改成仅麦克风录音。可以重新授权，或由用户主动选择另一种采集方式。

请使用浏览器支持的安全访问环境（例如 HTTPS 或本机地址）。系统/浏览器不提供会议音轨时，本功能不能绕过该限制。

## 隐私与声音质量

- 推荐佩戴耳机，避免会议声音经扬声器再次进入麦克风，导致重复录音或回声。
- 共享系统音频可能同时包含通知、其他应用播放的声音，应在面试前关闭无关声音。
- 平台只将混合后的音频送入原有实时转写和分段录音接口；共享画面仅用于浏览器共享生命周期，不作为视频上传。
- 音频混合本身不等于可靠的说话人识别。沿用现有角色识别和人工纠正，分析前应核对候选人/面试官标记。
- 语音转写服务不可用时，页面进入手动记录方式，不采集麦克风或会议声音。

## 暂停、继续与结束

- **暂停**：提交当前短录音片段，停止录音计时和实时音频推送；混音输出静音，但共享授权保留，界面仍可能显示浏览器共享状态。
- **继续**：若原采集仍有效，直接恢复，不重复申请共享权限。暂停时间不计入录音时间。
- **共享停止或设备断开**：自动暂停、提交当前片段并释放采集资源，不自动回退到仅麦克风。页面提示重新授权后继续，原有会话继续复用。
- **结束或离开页面**：停止所有输入/输出音轨、音量定时器及音频处理；结束面试仍使用原有会话保存和评分表读取流程。
- 音频文件按原有 15 秒机制连续分段上传；展示层按已有发言合并逻辑呈现完整回答，不把每个传输包当成一条回答。

## 查看和保存原音频

- AI 面试室标题与“AI简历题”之间新增“查看原音频”入口，面试进行中和结束后均可查看。
- 弹窗按会话开始时间、录音片段偏移排序，支持原音频播放、连续播放下一段和下载当前片段。录音沿用采集时的独立分段，不将多个 WebM 文件直接拼接为一个文件。
- 音频上传后先保存文件和独立的数据库索引，再执行转写；没有识别出文字或识别服务报错时，也保留已上传的原音频。相同会话、时间偏移与音频内容的上传重试复用同一条录音记录。
- 文件保存在配置的对象存储中，本地模式使用现有录音存储目录；索引保存在 PostgreSQL 的 interview_audio_recordings 表。查看与下载均校验登录、企业工作空间和面试访问范围。
- 升级会回填历史转写记录引用的音频。历史上未曾上传、已经丢失的文件不能补录；历史转写失败且没有留下关联记录的文件不在本次自动回填范围内。
- 面试中需要回放时推荐使用耳机，避免回放声音再次被麦克风采集。新片段完成上传后，点击“刷新列表”查看。

## 2026-10-20 面试总结加载与生成稳定性

- 实际失败记录在模型调用约 120 秒时超时。完整对话此前在转写和问答中重复传入；现使用短引用关联问答，仅传一份完整转写，不截断对话。该记录的模型输入从 66,873 字符降至 31,469 字符。
- 总结使用独立超时预算：普通面试至少 180 秒，100 段及以上转写至少 300 秒，上限 300 秒。网络中断、超时及部分临时 HTTP 错误最多自动重试一次，每次使用独立超时信号；认证失败或响应证据不合格不自动重试。
- 后台同时处理最多两个总结任务。会话读取失败会退出生成状态；过期任务、版本与领取标识校验继续由数据库保证。
- 重新生成期间保留原报告和转写。页面读取失败后以 2.5–15 秒间隔自动重试，继续检查后台进度；关闭窗口不取消后台生成。旧读取响应不会覆盖较新的生成状态。
- 不放宽评分证据要求。无法确认说话人、混合发言或时间重叠的内容保留在完整转写中，不自动作为候选人评分依据；未问的参考题不扣分。
- 验证：API 总结与转写 HTTP 测试 67 项、前端总结弹窗测试 11 项、真实 PostgreSQL 隔离回滚测试 1 项通过；前后端构建与前端类型检查通过。原失败记录实际重新生成成功，保留全部 314 段转写，页面已显示报告。历史说话人归属问题仍需独立核实。

## 2026-10-20 整场音频、线上双路与对话回听

- 查看原音频默认显示一份整场连续录音，支持拖动、倍速、整场下载；多次采集可切换场次。后台保留独立上传的原始录音块，按实际采集时间合成，保留停顿和双路重叠，不使用转写结束时间裁掉原音频。首次整理后缓存 M4A，新增录音会生成新的缓存版本。
- 线上面试保留麦克风和会议音频两路，可查看完整对话或单独回听一路。两路独立试音，麦克风有声音不会掩盖会议音频未采集的问题；正常倾听时的静音不反复告警。音源来源不直接等同于面试官或候选人。
- 转写按采集时间从上到下展示，保留同时发言并标注重叠；音源、声学说话人编号和人工确认的角色分别显示。每段可跳转到整场录音对应时间回听，保留已有角色纠正入口与评分证据限制。
- 历史来源未记录的录音仍可整理整场回放，但不能恢复出不存在的独立音轨。正在录制或还有待上传音频时显示“已保存部分”，上传后可刷新。没有原音频或原文件损坏时明确报错，不生成缺段的成功录音。
- API 运行环境需要 FFmpeg，系统 PATH 或 FFMPEG_PATH 可指定；部署镜像已安装。整场接口沿用面试访问范围校验，清单同时约束面试和采集场次，支持私有响应及 Range。限制并发整理数和处理时长，防止大量请求拖垮服务。
- 验证：前端相关 156 项、API 音频与转写 HTTP 30 项、真实 PostgreSQL 隔离回滚 1 项通过，前后端构建与前端类型检查通过。真实 FFmpeg 合成测试验证停顿、两路重叠、音源隔离和音频尾部不被转写时间截断；未替代真实双人线上通话验收。
- 本地 API 已完成常规构建并重启，健康检查正常。浏览器使用已有录音验证连续 M4A 解码、按发言时间定位、音源切换保留进度与倍速，以及整场下载。此前本文件中“未重启共享 API”的说明为当时状态，以本次激活记录为准。
